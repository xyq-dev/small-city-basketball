# 球员比赛数据与同价对比使用说明（C07）

适用于本次球员预约模块的数据展示、对比和授权功能。本文说明当前实现的操作与数据口径；分支整合、测试和正式部署状态见 [C07任务](tasks/C07.md) 与对应交接，不作为上线公告。预约流程和资金边界继续见 [球员赛事预约使用说明](PLAYER_BOOKING_USAGE.md)。

## 页面入口

| 入口     | 路由                             | 可做什么                                                             |
| -------- | -------------------------------- | -------------------------------------------------------------------- |
| 球员广场 | `/players`                       | 按姓名/地区/自述、位置、可约日期和参赛费筛选，查看简要统计，加入对比 |
| 球员详情 | `/players/:profileId`            | 查看“已授权比赛记录”、样本完整度、最近5条有效确认记录和未采集项      |
| 球员对比 | `/players/compare?ids=:id1,:id2` | 比较2至3名当前可查看球员；第3个编号同样通过ids传入                   |
| 数据授权 | `/player-data`                   | “比赛数据授权与提名”：主办方提名、本人同意、拒绝或撤销               |
| 球员中心 | `/player-center`                 | “我的比赛数据授权”：处理本人档案收到的提名                           |

机构导航还有“球员数据授权”；预约页导航显示“数据授权”。具体可见内容与操作按钮以服务器返回的当前权限为准。

## 领队如何比较同价球员

1. 在“球员广场”选择位置、可约日期或“参赛费同价筛选”。某个球员卡片上的“找同价同位置”会同时设置其位置和参赛费筛选。
2. 阅读“已授权统计”的统计场次、每场记录得分/犯规，再看本人自述、地区与档期。位置、身高和打法来自球员本人资料，不是平台能力评级。
3. 点击两位或三位球员的“加入对比”，再在下方对比栏点击“开始对比”。已选球员可以移除或清空；最多3人，少于2人不能开始。停用或不可查看的球员不能继续比较。
4. 对比页“同价，也要看记录与适配”并排展示参赛服务报价、当前平台费、含交通食宿的预计合计、位置/身高、完成服务记录、个人统计场次、每场记录得分/犯规、数据完整度、授权来源和最近记录。
5. 需要更多上下文时点击球员姓名进入详情；选定后点击“预约这位球员”进入原预约表单。不同样本数、赛制和记录完整度不能直接当成实力排名，系统不生成综合战力分。

### 同价不等于含费总额相同

同价筛选只比较球员的参赛服务报价，不含平台费、交通或食宿。对比页的“预计合计（含平台与交通食宿）”按当前报价与费率估算，最终以预约确认页及服务器返回的报价为准。

例如在10%试运营费率下，两位球员参赛费都为300元：

| 项目       | 球员甲 | 球员乙 |
| ---------- | -----: | -----: |
| 参赛服务费 |  300元 |  300元 |
| 平台服务费 |   30元 |   30元 |
| 交通费     |    0元 |   80元 |
| 食宿费     |    0元 |    0元 |
| 预计合计   |  330元 |  410元 |

以上只是说明计算方式的示例，不是真实成交。交通食宿不计入平台服务费的计算基数。创建订单会核验领队审阅的球员资料和费率版本；报价变化时需要重新读取并确认，不能静默调价。

## 统计数字应该怎样理解

| 页面指标          | 实际含义                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| 授权来源          | 经主办方提名、本人同意且当前仍满足公开条件的赛事来源，不是比赛场数                                      |
| 个人统计场次      | 本人在该场固定名单中，并且存在当前有效、独立确认的`PLAYER_BASIC`个人记录的场数；包含真实记录为0的名单项 |
| 每场记录得分/犯规 | 有效个人记录的得分/犯规合计，除以上述个人统计场次                                                       |
| 已确认名单记录    | 当前有效确认的个人统计场次与仅球队统计场次；不是实际出场数                                              |
| 仅球队数据        | 该场为`TEAM_ONLY`，有球队结果但没有采集个人得分/犯规；不计入个人均值分母                                |
| 个人归属未完整    | 本队仍存在未归属给具体球员的得分或犯规；已记录给本人的数字保留，同时提示不完整                          |
| 完成服务记录      | 预约履约项当前为完成状态且未处于争议；不是付费成交、准时率或比赛出场证明                                |

**名单统计场次不代表实际上过场，更不代表上场时间。**现有采集会为固定名单中的球员保留0值，因此不能把名单出现次数改称“出场数”，也不能据此推算每分钟表现。

- `PLAYER_BASIC`有效记录为0时显示真实的0，计入个人统计场次。
- 没有个人采集、没有授权或没有有效确认时，个人指标显示“未统计”，不补0。
- 助攻、篮板、上场时间、投篮命中率尚未采集，均显示“未统计”；不根据得分、身高或自述推算。
- 最近5条有效确认记录可以包含`TEAM_ONLY`；这些记录的个人得分和犯规仍为未统计，并注明“仅球队数据”。
- 每个球员当前最多汇总最新1000项已授权比赛样本。出现截断提示时，较早记录没有计入当前合计和分母，不应解读为全部生涯统计。

## 主办方提名与本人同意

### 主办方操作

1. 用当前有赛事数据管理权的账号进入“数据授权”。机构负责人/管理员可以管理本机构赛事；其他工作人员需要有效机构成员身份及该赛事的`EVENT_MANAGER`分配。仅有机构级EVENT_MANAGER、记分权限或平台运营身份不会自动获得此发布权。
2. 在“主办方提名本人参赛记录”区域选择“有权管理的赛事”和明确的“固定报名名单成员”，再选择“提名到球员档案”。名单成员和预约账号通过明确编号关联，不按同名自动认领。
3. 填写“提名依据与原因”，说明如何核对对象，勾选有权提供有限统计的声明，点击“提名给球员本人确认”。原因中不要填写身份证、联系方式、保单或其他私密材料。
4. 提名后显示“等待球员本人同意”。这一步不公开个人统计，也不修改原报名名单或授予球员原私有赛事接口权限。

同一球员档案在同一赛事只能有一个待确认/有效成员关联，同一赛事名单成员也不能同时被另一个档案认领。发现错绑时先撤销，不通过编辑姓名把另一人的数据改给该球员。

### 球员操作

1. 使用球员档案所属账号进入“球员中心”的“我的比赛数据授权”，或进入“数据授权”。球员档案需已通过入驻资料审核，主办方才能向该档案提名。
2. 点击“核对本人记录并同意公开”，核对赛事、球队、固定名单成员和目标球员档案。
3. 明确勾选“我确认这是本人的参赛记录，并同意按上述有限范围公开展示”，填写处理原因，再点击“确认处理”。主办方、队长或平台运营人员不能代替另一个球员账号勾选同意。
4. 不愿公开或发现错误时，选择“拒绝本次公开”；已同意后可选择“撤销公开授权”。主办方也可以撤销其有权管理的来源。

授权记录每次读取50条，较早记录通过“加载更多授权记录”继续查找；本人授权与可管理赛事记录都会按当前权限分页，较早的有效授权不会因新历史记录增多而失去撤销入口。在球员中心只看本人授权时，即使当前页没有本人记录，仍可继续加载。打开同意或撤销前会重新核对该条当前版本和操作权限；权限刚失效时停止操作并提示刷新。

填写提名草稿或打开确认框期间暂不刷新/翻页，先完成或关闭当前操作。刷新、成功处理或切换账号会重新从第一页读取，旧账号未完成的翻页结果不会进入新账号列表。

一个账号可以同时是赛事管理者和参赛球员，并按当前权限先提名自己的固定名单记录，再单独明确同意公开。这仍是两个清晰步骤，**不等于双人独立审核、实名验证或自动证明人档一致**。比赛统计本身仍需沿用原记分系统的有效独立赛果确认。

## 公开范围、撤销与权限变化

公开部分只包含该球员有限的赛事名称、日期、赛制、本人记录得分/犯规、样本口径、完整度和完成服务数。不会公开其他球员名单、身份证、联系方式、保险材料、原私有事件或写入凭据，也不会因此开放原赛事后台。

授权有效与已有个人统计是两件事：双方都同意后，如果比赛尚无有效确认或只采集球队数据，个人指标仍可能是未统计。

- 撤销后，下次读取不再纳入该来源；撤销记录不恢复。需要重新公开时，主办方重新提名，球员再次明确同意。
- 主办方当前赛事管理权失效、提名账号停用、机构停用、球员账号或档案停用时，相关来源停止公开；停用球员档案的公开统计端点不可继续查看。
- 已打开页面不是实时推送。操作后可使用“刷新统计记录”“刷新记录”“刷新对比数据”或“刷新数据授权”取得当前结果；撤销不能承诺收回此前已经看见或保存的内容。

## 数据状态与异常处理

| 页面状态     | 应如何理解和处理                                                                         |
| ------------ | ---------------------------------------------------------------------------------------- |
| 暂无授权来源 | 当前没有可公开的双边授权来源；可能未提名、未同意、已撤销或来源权限失效                   |
| 尚无个人统计 | 有授权来源，但尚无有效`PLAYER_BASIC`个人样本；可能只有球队统计或未确认比赛               |
| 已有个人记录 | 当前样本有有效个人统计；仍须查看统计场次和分母说明，不等于实力认证                       |
| 部分个人记录 | 存在仅球队数据、待确认、来源无法核验、个人归属不完整或样本截断；按完整度提示使用有限数据 |

赛果重开后，旧确认记录立即退出当前统计；更正并重新独立确认后，只计入新的当前记录，不累加旧确认。当前来源损坏或无法核验时，不回退旧得分，失效样本不进入个人合计和分母，页面提示部分记录。

API读取失败会显示错误并停止展示旧统计，不用合成统计或0分填补。先刷新并核对当前授权、资料状态和原赛事确认情况；没有数据不代表球员能力差。

## 演示和资金

Mock模式有“交互演示/合成统计演示”标记，包含同为300元、控球后卫位置但报价合计和统计样本不同的合成球员。身份切换、提名/同意/撤销及对比用于演示，刷新整页会重置，不是现实比赛证据。

真实API沿用登录会话、机构/赛事权限及PostgreSQL。真实个人撮合支付和分账仍未接通；实收、退款到账、已结算金额均为0。完成服务记录不自动产生付款，也不会自动生成比赛数据授权或参赛资格；公开比赛记录亦不要求先购买球员服务。
