# 界面与交互规范

更新：2026-10-22｜性质：实施约束与交付边界；P01、P02、P03-A、P04-A已合并main（DONE / MAIN）；真实Web报名冻结、共享场地与单循环排赛已验收。P01 Mock与真实API模式分开，保险文件、小程序、其他赛制、记分及OBS页面仍按阶段规划。视觉参考见 [design/README.md](design/README.md)，业务依据见 [PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md)。

## 1. 统一视觉与导航

品牌固定为「小城市篮球」，宣传语「小城市，也有大主场。」。主色 `#132C49`，强调色 `#FF6B2D`，背景 `#F5F7FA`；颜色同时配合文字和图标表达状态。分数、计时和当前操作对象优先级最高，后台以任务和可操作信息为主。

四组图片是概念参考。实施需统一队徽、球员名称、赛事日期、比分与状态，不能逐图照搬互相矛盾的数据。生产页面不得出现示例人物的身份证或真实联系方式。

小程序底栏：**首页／赛事／视频／我的**；领队从“我的球队”进入管理。机构后台、平台运营和现场工作台使用独立角色导航。尚未开放的功能注明“规划中”或隐藏，不能保留点击无反馈的伪功能按钮。

## 2. P01：机构后台四页

P01 统一显示「演示模式 · Mock 数据」，机构上下文为示例机构。桌面双栏布局，窄屏可收起侧栏；至少检查 1440、1024、390 像素宽度，不要求把机构后台替代小程序。

| 页面 | 内容与交互 | 验收重点 |
|---|---|---|
| 工作总览 | 示例机构、赛事数量、我的赛事、快速创建入口；无对应数据的待办不编造 | 入口能到赛事列表、创建及指定赛事详情，数量来自同一演示数据源 |
| 赛事列表 | 按名称搜索、按状态筛选、结果数量；展示标题、日期、赛制、状态、地点；“创建赛事”主按钮 | 搜索/筛选可组合；无结果可清空筛选；新建后可定位条目 |
| 创建赛事 | 单页表单，保存草稿、取消返回；保存中禁止重复提交 | 字段错误保留已填内容；保存成功跳转详情；不提供真实发布、支付或购买按钮 |
| 赛事详情 | 标题、草稿状态、基本信息、编辑入口；后续模块显示明确规划状态 | 可编辑并回到同一详情；不存在的 ID 有返回入口；不能把草稿显示为已开赛 |

### 创建与编辑字段

| 字段 | 规则 |
|---|---|
| `name` 赛事名称 | 必填，去首尾空格，1–80 字符；同名允许，依靠 ID 区分 |
| `startDate`／`endDate` | 必填日期；结束不得早于开始；原型不强制必须是未来日期 |
| `timezone` | 默认 `Asia/Shanghai`，P01 固定展示；后续多时区由后端支持 |
| `venueName` | P01 可选，最多 100 字符；空值显示“待定”，不伪装成已预订场地 |
| `format` 赛制 | 必选：循环赛、分组后淘汰、单淘汰；仅作为草稿配置，不表示原型可生成赛程 |

赛制字段机器值由统一数据/API 契约管理；不得在多处自行翻译成不同枚举。新建仅产生 `DRAFT` 草稿。P01 默认使用内存演示数据，页面明确提示“刷新后重置”；如后续任务改用本地持久化，需同步调整说明与清除入口。

## 3. P02：真实API模式

P02新增注册／登录／退出、当前机构切换和会话恢复。API模式使用当前机构的真实赛事，创建后刷新仍可见；Mock模式仍保留演示标识及刷新重置提示，两种数据不能混用。

- 请求失效或退出后返回登录流程；机构切换隔离旧请求结果，不用上一个机构数据填充新机构页面。
- 创建入口按机构权限展示；详情编辑按服务端逐赛事 `permissions.canEditDraft` 判断，403／404／409提供明确反馈，最终写权限仍由后端核验。
- HTTP读取或后续分页失败时显示失败与重试，不静默退Mock或把部分列表当成功；保存失败保留输入。
- 邮箱账号不代表邮箱已验证，也没有微信登录、密码重置或平台运营页面。

### P03-A：已交付Web报名与审核

本节功能在真实API模式可用，使用PostgreSQL持久化；P01 Mock仍是显式内存赛事演示，不伪造报名/审核/冻结成功。

- 个人账号仅创建登录身份；机构工作台与“我的球队”分开选择，teamContexts不混入工作人员organizations。当前User ID用于机构明确签发领队邀请，不根据邮箱自动获得权限。
- 球队页维护长期成员、领队邀请和授权；邀请令牌只在签发时提供，链接fragment读取后移除，接受后刷新授权。撤销未消费邀请与停用已接受grant分开，旧会话也不能绕过撤权。
- 领队只看可报名赛事及本队报名，选择当前成员、填写号码并保存新名单版本；保留0与00规则反馈。提交后只读，获批后先由独立审核者退回才能修改；保存、补交及重提不覆盖旧名单。
- 工作人员按实际赛事分配查看报名、规则及审核动作；拒绝/退回展示原因，自审受后端阻止，不能仅靠隐藏按钮。关闭报名后不允许新建或提交DRAFT，只允许已有退回名单补交。
- 冻结操作展示获批队及排除数量，确认后保存不可变freeze并转只读；冻结不会发布赛程或显示“已排赛”。版本冲突提示重读，失败保留输入且不退Mock。

已完成桌面/手机Chromium的真实Web闭环，不代表微信小程序或真机验收。球员身份证、保险凭证上传、邮件验证、微信登录和OBS仍未接入；排赛新增范围见下节，不能把页面地图整体视为完成。

### P04-A：已交付单循环排赛

真实API模式新增以下机构页面；球队模式不会进入后台排赛或发送空机构请求，Mock仍不提供真实排赛操作。发布仅形成后台正式计划，不自动开放匿名或微信观赛页面。

| 页面 | 路由与内容 | 已交付交互 |
|---|---|---|
| 抽签排赛 | `/scheduling`，可见赛事及机构场地入口 | 明确2–32队单循环边界，未冻结或不支持的赛事显示业务原因 |
| 机构场地 | `/courts`，机构共享场地列表 | 按能力创建、编辑名称／启停；未来正式占用阻止停用，取消不提交，失败保留输入 |
| 赛事排赛 | `/events/:eventId/scheduling`，冻结来源、规则、完整对阵、轮空与手工安排 | 生成、按轮编辑、全量保存、取消本地修改、检查和定位冲突、确认发布 |
| 历史与正式计划 | 当前页正式赛程或 `/events/:eventId/scheduling/history/:revisionId` | 查看上一版及原因；已发布计划只读，保留发布时的队名、场地名与时间 |

- “每场占用分钟”明确填写1–1440整数，“最少休息分钟”为0–43200整数，“最小日期间隔”为0–365整数。无间隔也需显式填0，不暗设放宽条件。场地窗口1–200个，同一场地窗口不能重叠；开始／结束时间及逐场输入明确为中国标准时间，不采用浏览器所在地时区。输入控件16px，主要触控目标至少44px。
- 对阵来自不可变冻结名单。按轮查看不会丢弃未显示场次的安排；保存发送本稿全部场次和赛事／修订双版本。场地与开始时间需同时填写，取消分配同时清空二者；保存前持续标记“本地修改未保存”，取消修改不写服务端。
- 检查只针对已保存版本；未分配、窗口／赛事日期越界、停用场地、场地／球队重叠、最少休息和日期间隔问题可定位到本方场次。外部占用不显示无权访问的赛事名称或名单。本地修改或准备重抽使原检查失效；取消重抽后也需重新检查旧稿。
- 动作由最新服务端capabilities决定。版本冲突保留输入并提示重读，任何分页后页失败都整体报错；API模式不退Mock。发布时新增的冲突会清除旧绿色通过状态，显示最新问题并阻止继续确认。
- 正式发布先显示球队数、轮数、场数、共享场地数、时间范围、占用／休息／日期间隔及只读后果；取消不提交。服务器发布事务再次检查最新占用；一次成功后隐藏编辑、重抽和重复发布入口。正式场次初始待开赛，不显示比分或假直播。

## 4. 后续页面地图

| 使用端 | 页面 | 主要动作与边界 |
|---|---|---|
| 观赛小程序 | 首页、赛事中心、赛程、积分榜、比赛详情、球员档案、视频、我的 | 仅展示已发布内容；未开始、进行中、待确认及正式结果有不同标识；视频不可用时展示原因 |
| 领队／球员 | 我的球队、成员邀请、本届名单、资格资料、保险凭证、提交确认、审核进度、消息 | 区分长期档案与本届名单；本人/领队权限不同；退回可见原因并定位待补字段 |
| 机构后台 | 报名审核、单循环排赛首卡已交付；其他赛制、改期、赛果确认、内容交付、品牌赞助及套餐用量后续建设 | 已交付范围见上文；未来调赛需显示影响及冲突，不能以当前一次发布入口替代 |
| 现场工作台 | 赛前检查、主端接管、基础/专业记分、换人、操作记录、终场确认 | 当前球队与球员持续可见；得分、撤销、结束分区；离线、待同步、已同步、冲突不能混用 |
| 直播工作台 | 比赛绑定、包装模板、只读地址、画面预览、推流配置、事件标记、录像映射 | 包装地址可轮换；密钥默认遮挡；数据时间与连接状态分开，OBS 中断不阻断记分 |
| 平台运营 | 机构开通、服务套餐、额度调整、服务记录、审计 | 与机构后台分开；访问敏感资料需明确授权和审计；不预设真实订单、收入及客户数量 |

现场记分台优先适配横屏平板和电脑；观赛和报名优先手机。专业统计与基础记分使用明确模式，不用“0”填补未采集字段。

## 5. 所有页面的状态规范

| 状态 | 必须表现 |
|---|---|
| 加载 | 保留布局，给出正在读取的反馈；保存操作有独立状态，避免重复提交 |
| 首次空数据 | 说明当前没有内容，并给出当前角色可以执行的下一步 |
| 搜索无结果 | 保留条件，提供清空筛选；不要误报为整个系统无赛事 |
| 失败 | 保留可恢复输入，说明失败动作，提供重试或返回；错误记录不带敏感资料 |
| 无权限／不存在 | 不回显受限资源详情；提供返回可访问列表的入口 |
| 只读 | 清楚说明原因，如已锁定、仅观赛或非主记分端；不能只把按钮变灰 |
| 离线／陈旧 | 显示同步状态及最近更新时间；未确认的操作不能显示“已保存到服务器” |
| 未开放 | 说明属于后续阶段，不伪造成功状态、直播画面、交易或通知送达 |

表单采用可读标签和就地错误提示；键盘可聚焦所有主要控件；手机主要触控目标建议不小于 44×44 逻辑像素。危险操作明确对象和后果，结束比赛与普通记分按钮保持距离。
