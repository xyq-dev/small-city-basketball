## 2. 最小交付目标

完成：标准地区目录 → 观众手动选省／地级／县级或全国 → 真实公开赛事筛选 → 主办方标准上架／更正 → 旧客户端和旧文字查询继续可用。

按 C21 方案执行以下决定：

- 使用固定 `yescallop/areacodes@e2c2b2e1fb4ce1fb76e879aa0b80e229adaf950c` 的 `data/2025.txt` 和 CC0 许可；校验完整文件哈希与 3212 条数据。版本 `cn-admin-2025-r1`，明确截至 2025-12-31，港澳台仅省级，非当前全量官方认证。
- 使用方案给定 namespace／UUIDv5 初始 registry，地区 ID、来源代码、显示名称分离。支持直辖市、省直管县及无县级下辖的地级叶子，不伪造三级节点。
- 省包含全部实际下级，茂名包含高州，高州不包含只确定到茂名的记录。全国保留未知、歧义、空标签，但仍执行全部公开授权条件。
- 旧 city 精确匹配与 v1 游标原样保留；新地区请求使用 regionId ＋ catalogVersion 和 v2 游标，同 SQL 筛选／排序／分页。
- 旧标签只做无歧义精确读取关联，不回填；只有完整唯一正式名称及方案批准的三个短名。不得自动去后缀、模糊猜测或根据机构／GPS 推断。
- 匿名赛事 DTO 仍严格八字段。新增地区参考 DTO 不能携带业务内部 ID、用户信息或坐标；公共请求不读写 Cookie，保持 no-store 和限流。
- 更正采用 REPLACE_REGION，同事务撤旧、建新、审计、赛事版本仅增加一次；旧 listing 永久保留，分享身份不变。不要直接 UPDATE 城市／地区字段。
- v1 本机偏好迁移为 LEGACY_CITY，用户确认后才改成 REGION；全国／历史文字／标准地区明确区分；设置页选择地区与首页浏览偏好相互独立。
- 保持 C17/C20 的确认、会话、页面代次和迟到响应保护。发送后超时按结果未知重读，不能当取消或自动重发。

## 4. 实施步骤

1. 固定原始数据、LICENSE、manifest 和稳定 registry；实现可重复生成器，验证 hash、覆盖、父树、唯一名称与三个短名。生成器只读本地固定输入，不做数据库写入或联网更新。
2. 编写新增迁移（编号执行前核验）：三张参考表、不可变 guard、listing 两个可空字段及 FK、必要索引、原 guard 的地区不可变检查；旧 listing 只新增 NULL，不回填、不自动重列。完成 runtime 最小权限与 readiness 哈希检查。
3. 按方案补地区 DTO 与匿名目录 endpoint，再扩展 directory 查询／游标和 REPLACE_REGION。每一项保留旧 API 回归。
4. UI 先按方案页面状态落地：city-select 层级／搜索／完整路径／部分覆盖／错误恢复，home 和 watch 联动，event-setup 独立选地与更正确认。不要先写假城市或假赛事占位。
5. 增加真实页面 →API 流程；验证历史标签、标准地区、全国、上架、更正、撤出及分享。补并发、DB 权限和未知结果测试。
6. 完成新增表对应的备份／恢复／重启适配及隔离 CI；保留旧 C20 包恢复旧 78 表归档后再升级的明确路径，不把旧包能运行新 Schema 当成兼容目标。
7. 同步根 API_CONTRACTS、DATA_MODEL、微信 README、实施任务／交接，以及 C21 方案中的实际实施注记；计划与事实分开。
