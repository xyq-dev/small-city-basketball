## 在线记分运行边界

P05-A要求显式篮球基础规则，首次READY后赛事规则锁定。OWNER/ADMIN须另获本场有效SCORER分配才可写分，最小场次人员无需EventStaff但不能因此读取整个赛事。确认独立于实际记分：历史开始／结束／计时／记分／更正人员、当前主写者及当前任一球队有效领队均被排除，OWNER无例外。原规则、冻结名单、正式计划、已确认版本及事件历史不能被运维直接覆盖；需要更正时按有理由的修正／重开／重确认流程处理。OVERTIME平分修正仍待处理，本卡不提供回LIVE补加时或弃权／争议捷径。

控制租约为30秒，客户端10秒续约；session、每tab内存身份、leaseId及fence共同限定主写端。控制凭据不持久到浏览器存储；过期心跳／释放不能复活旧租约。刷新或退出后重新取得控制，不能复制另一tab凭据继续写。停用已有但机构成员／用户已失效的assignment可清理残留授权并使该人员租约失效，启用仍要求有效成员。租约过期与人员离线不会自动暂停正在运行的比赛时钟。

raw clock的remainingMs对应anchorServerTime，而非每次读取时重新存下的倒计时；显示按serverTime及锚点扣时一次，最低0。DB重启后同一锚点继续计时，剩余0不自动FINAL；暂停、校时及换节都须显式命令。事件按服务器seq而非客户端capturedAt排序。FINAL只表示本场独立确认；不会自动COMPLETED赛事或接通OBS。P05-A仅授权私有快照／历史；P05-B feature另行显式发布排名规则、启用有限公开观赛，尚未验收，不会因记分工作台存在而自动启用。没有SSE/outbox或直播推送服务。

超时／5xx／断网时停止新写，保留本页原envelope及commandId并先核对原身份的receipt和当前snapshot；查无回执不是永久失败证明，不自动换ID、改版本或用新fence重放旧加分。已提交重试重新鉴权，同内容返回原receipt及当前snapshot，不再写分；receipt.appliedVersion与当前snapshot.version可以不同。基线／控制或权限变化时人工核对后恢复。未确认命令仅在页面内存中，页面销毁或浏览器进程崩溃后不承诺恢复；本卡不提供可靠离线队列。操作步骤见[开发说明](DEVELOPMENT.md)。

## 备份、恢复与故障处理

P02/P03-A/P04-A/P05-A的数据库重启持久化检查不是备份恢复演练，正式灾备能力尚未验收。正式启用前确定恢复点与恢复时间目标，覆盖数据库、未来保险附件、赛事媒体元数据和配置；具体保留天数及备份频率按试点规模与成本确定。至少在隔离环境实际恢复一次，验证赛事、名单、授权、正式计划、记分事件／收据、投影、确认历史及迁移校验和一致；已释放租约和单调fence也须保留，不能恢复成可重用旧控制。后续加入附件或媒体时补相应恢复验证。仅有“备份成功”日志不足以证明可恢复。

优先监测 API 错误、授权失败、事件积压、记分版本冲突、主端租约、同步延迟和直播用量；日志不得包含完整证件或令牌。发生记分异常时保留服务器事件、收据、版本和本页尚存的未知结果命令，暂停新写并联系赛事负责人核对，不直接修改数据库比分、删除事件或回执消除告警。清缓存、重置浏览器存储、刷新页面或重新seed都不能恢复已丢失的未确认命令，也不能替代数据库恢复；不得靠重置lease/fence或删除projection绕过控制权和历史一致性。处理结束后记录影响赛事、时间范围、修复依据和遗留任务。
