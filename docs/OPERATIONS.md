P03-A的球员资料为长期成员姓名及本届名单姓名／号码快照，未接身份证核验、保险附件、对象存储、微信或OBS。规则要求身份／保险时阻止开放报名，不默认豁免。后续报名资料只收集完成资格审核所需字段；附件存储与公开媒体分开，下载须重新校验归属和权限，导出、查阅与删除保留审计。展示默认脱敏，设定保存期限和删除流程。保险凭证提交、赛事方审核及保险服务商实际承保是不同状态，不能仅凭图片上传保证保单有效或保障范围。

邀请仅绑定已存在UserId，不把未验证邮箱当作可信受邀身份。原始令牌只在签发时返回一次；分享使用fragment，读取后清除，不落浏览器存储或日志。已接受邀请不能替代当前grant，停用领队后旧Cookie也不得继续写入；授权支持人员应通过服务端授权流程处置，不直接改历史名单或freeze。

## 发布与数据库变更

每次发布记录来源分支、提交SHA、测试证据、配置变化、执行人、时间和结果。用户已有项目范围授权，执行按根AGENTS和当前会话核验，不重复申请；本文件不另行创造授权，也不能把尚未配置的生产设施或预算视为已具备。

Migration 必须区分“设计”“已编写”“测试环境已执行”“生产已执行”，记录环境与执行结果。先验证旧版本兼容性、锁表及数据量影响；能分阶段扩展、回填、切换、清理的变更分阶段完成。生产执行前按任务授权核验备份与恢复路径，不能因文件存在就声称数据库已更新。

代码回滚与数据库回滚不是同一动作。优先回退应用并保持兼容；不可逆数据变更不能盲目运行反向脚本，需评估恢复时间和新增数据损失。任何回滚或恢复均按授权范围执行，并在事后验证核心读写及机构隔离。

## 备份、恢复与故障处理

P02/P03-A/P04-A的数据库重启持久化检查不是备份恢复演练，正式灾备能力尚未验收。正式启用前确定恢复点与恢复时间目标，覆盖数据库、未来保险附件、赛事媒体元数据和配置；具体保留天数及备份频率按试点规模与成本确定。至少在隔离环境实际恢复一次，验证已实现的赛事、名单、授权及历史可用；后续加入附件或事件时补相应恢复验证。仅有“备份成功”日志不足以证明可恢复。

优先监测 API 错误、授权失败、事件积压、记分版本冲突、主端租约、同步延迟和直播用量；日志不得包含完整证件或令牌。发生记分异常时保留事件和本地待同步队列，暂停冲突写入并联系赛事负责人核对，不直接修改生产比分消除告警。处理结束后记录影响赛事、时间范围、修复依据和遗留任务。

## 商业交付与成本

初期按届服务、视频单独计量，套餐可人工开通；价格、税务和合同条款尚未确定。每项额度说明统计单位、周期、超额行为、到期处理和更正办法；不得因套餐到期删除历史赛果。报名费、保证金、软件服务费分别建账；在支付退款设计审查前不实施自动扣款、资金托管或罚款结算。

每届交付清单包括确认赛果、成绩册、榜单及宣传素材；视频服务另列录像、集锦、保存期限与失败补交方式。记录视频转码、存储、分发流量和人工支持成本，限制未经批准的高成本任务。赞助报告区分真实观看、曝光、点击及统计口径，不把模板展示或演示数值当成交付成果。

建议以青锋杯验证流程，再争取三家无关联主办方付费试点，记录交付工时、成本、付费与续用反馈。该试点尚未实施；收入、客户和指标不得写成既有成果。
