# 测试与验收

版本：0.1；更新：2026-10-22（Asia/Shanghai）。本文定义后续验收要求，不代表测试已经执行。

## 当前证据边界

本轮开始时仓库仅有文档和四组 UI，无应用、数据库或测试环境。应用测试、构建、类型检查、端到端测试、性能测试和真实 OBS 接入均未执行。实际执行记录由任务交接单保存，并汇总到 `CURRENT_STATUS.md`。

实施任务必须给出所测提交、环境、命令、结果和证据位置；人工检查写明步骤与观察结果。不能把设计审查、Mock 演示或文件存在当成生产验收通过。命令只能引用当前项目真实存在的脚本，不提前宣称某个安装或测试命令已经可用。

## 分阶段必测范围

| 阶段 | 必要检查与验收 |
|---|---|
| P01 前端原型 | 工作总览、赛事列表、创建赛事、赛事详情可访问；必填、边界值和取消行为正确；创建结果可在列表及详情查看；未知赛事有明确提示；加载、空、错误状态可演示；Mock 标识清楚；说明刷新是否重置数据；桌面与平板布局无关键遮挡 |
| P02 机构与权限 | 至少两家机构及多种角色；对详情、列表、搜索、导出、附件与订阅尝试跨机构访问；伪造机构 ID 无效；撤销权限后旧会话不能继续执行受限操作；普通成员不能调用平台管理接口 |
| P03 报名审核 | 外部领队/球员无需工作人员身份也能完成获授权流程；邀请冒领、重放、过期及撤销均正确处理；本人和领队的资料权限不同；重复报名及重复球员按规则处理；退回补资料能重新提交；提交、审核、名单冻结有版本冲突提示；球队长期成员变动不改变已冻结赛事名单；保险凭证只能由获授权角色读取，界面不把上传成功等同于审核通过 |
| P04 抽签排赛 | 不重复、不遗漏，种子队与人数约束正确；同队时间、场地占用及休息间隔无冲突；无解时报告冲突规则；固定输入和随机种子可追溯；手工调赛重新校验；发布后的改动保留版本和通知依据 |
| P05 记分赛果 | 见下节；结束比赛进入待确认，未经确认不作为正式赛果；确认与更正后榜单重算一致；并列排名按赛事规则解释，不能静默采用未配置的规则 |
| P06 OBS 与内容 | 只读包装不能写比分；令牌撤销后连接失效；展示字段不含个人敏感资料；断线可恢复且不会把旧比分覆盖新比分；OBS 关闭不影响记分；比赛时钟暂停时录像时间仍独立；剪辑失败和缺素材有可重试状态 |

## 记分系统必须证明的行为

- 同一操作重发、重连重试或服务重启后重放，只计入一次；同幂等键不同内容必须拒绝。
- 两端争抢主记分权时仅有效持有者可写；租约失效后的离线端不能继续覆盖服务端结果。
- 并发记分使用已知版本校验；失败操作明确标记待处理，不能伪装成已同步。
- 更正采用可追溯事件，比分、球员统计、赛况、榜单与公开包装保持一致；重放同一事件序列得到相同结果。
- 断网操作在本地有明确状态；重连先核验主写权、事件版本及名单，再同步；发生冲突需处理，不能简单以最后到达的数据覆盖。
- 跨节、暂停、恢复、校时、更换主端及页面刷新不导致重复计时；未采集的数据展示“未统计”。
