## 1. 已有能力与本次范围

`apps/api/src/insurance-provider.ts` 已定义商品、报价、申请、原单查询、撤销端口；`insurance-service.ts` 已有加密资料、独立资格预审、监护与数据同意检查、幂等回执、持久任务、外部付款入口、保单事实、取消和查单编排。`expansion-services.ts` 已装配授权读取器，`packages/contracts/insurance.d.ts` 已提供订单视图。尚无真实保险公司或持牌中介适配器，不能把现有测试通过解释为真实承保通过。

首版接一家经审核的服务方，限定已核验地区、赛事类型及成年人自助场景；未成年人入口保留资格说明和外购保单，只有补齐供应商投保人/被保险人/监护关系协议与测试后才开启。继续支持现有外购保单人工审核。不开平台保费钱包，不把保险保费接入比赛费用交易订单，不做自动比价推荐。

正式在线销售主体、销售页面归属、平台可展示及可提交的信息范围必须先由业务、服务方及专业审查明确。现有 `quote/apply` 技术端口不代表平台已获准开展相应业务。若认可模式仅允许服务方自营页面完成销售，则报价确认、告知、投保及付款均在该页面完成；平台端口仅承接经批准的数据交换和状态同步，不能为了套现有代码保留不适用的销售动作。

## 2. 接入合同与商品准入

供应商未选定，本文不指定真实 HTTP 地址或宣称已签合作。选型时须取得并版本化：主体资质及合作边界、正式 API/沙箱、认证与验签方案、固定出口/允许域名、幂等规则、原申请号查单能力、产品及条款版本、付款/核保/出单/取消/退款语义、服务时限、故障和理赔投诉联系人。

每个商品核验地域、年龄、业余篮球赛事及训练活动适用范围、除外责任、等待期、生效规则、保额与赔付条件、退保/批改要求。现有 `basketballCovered` 布尔值不足以证明某场赛事适用，拟增审核快照及生效期限；证据失效即禁新单。页面展示“适用范围待确认”时不能标成可投保。条款 URL 仅来自审核域名，同版本内容变化拒绝覆盖。

现有配置通过 `insurance_configuration` 固定 provider/key，订单记录 `org_id/provider_id`。首版沿用单供应商，在服务端增加组织白名单；组织由报名归属推导，客户端不能指定供应商、商户或回调地址。已有订单固定原 provider、产品/条款、资料版本、赛事日期及操作号。更换供应商不得改写旧单；需要历史驱动共存时另做配置版本扩展，未支持前不得切换带未决订单的配置。换钥须先完成历史密文可读的独立迁移。

## 3. 用户流程与界面

流程：报名成员 → 资格预审/身份和必要同意 → 保障资料 → 服务方投保确认与付款 → 返回查单 → 已出单且资格核验成功 → 赛事审核。支付成功只代表付款，不能展示为“已保障”；理赔由合同指定服务方处理。

| 页面/区块 | 内容与状态 | 交互规则 |
| --- | --- | --- |
| 报名保障卡 | 未接入、资料缺失、预审中、待确认、待付款、出单中、有效、待核对、失效 | 永久保留“提交外购保单”；错误显示具体下一步 |
| 商品/告知页 | 服务主体、适用范围、条款版本、日期、保费来源、退出入口 | 不默认勾选；按获准模式跳服务方；不承诺一定承保/赔付 |
| 付款返回页 | 原订单号、最后核验时间、独立付款/保单状态 | 查原单；无结果显示“处理中，请勿重复购买”；返回参数不改状态 |
| 保单详情 | 掩码保单号、保障起止、下载、服务方理赔/投诉入口 | 下载重新校验本人权限；不能以分享链接公开证件或保单 |
| 退保页 | 原单、服务方确认的可退金额/规则、申请状态 | 二次确认；未确认可退额显示“待服务方核定”，不估算到账承诺 |
| 运营核对台 | 原操作号、租户、事实时间线、错误码、查询预算、人工工单 | 脱敏；只允许原单查询/登记证据，不能人工点击“出单成功” |

资格校验区分成年本人、未成年被保险人和合法投保人。沿用参赛授权不等于自动取得保险投保授权；现有 `InsuranceApplicant` 把身份放在单一对象，未成年人正式上线前必须扩展并验证关系与同意版本。给服务方仅传其明确要求的最少字段；参赛档案中照片、签署文件不因存在而全部上传。身份信息加密，日志仅不可逆关联号；导出、查看和保留期限均纳入访问审计。

## 4. 状态与异常边界

| 维度 | 正常路径 | 异常处理 |
| --- | --- | --- |
| 付款 | `UNPAID → PENDING → PAID → REFUND_PENDING → REFUNDED` | 明确失败可 `FAILED`；不能用退款申请替代退款事实 |
| 保单 | `PENDING → ISSUED → CANCEL_PENDING → CANCELLED` | 明确拒保为 `FAILED`；已付未出单持续核对并建立退款/人工任务 |
| 外部操作 | `PENDING → RUNNING → 已确认结果` | 超时/断连/响应验签失败为 `UNKNOWN`；恢复租约后只查原申请号 |

状态为现有两个事实维度加任务状态，界面不合并成单个“成功”。`query(operationId)=null` 只表示未获得可确认结果，不能新建第二张申请或释放未决门禁。现有每轮自动查询预算为 12，预算耗尽进入人工核对/显式重开查询；重开不换原号、不重发可能扣费的申请。迟到响应、取消与出单交叉、旧任务回写都必须通过租约围栏和绑定校验。

回调按供应商真实协议验签、限时、防重放，转换为内部通知；现有内部通知密钥不能冒充供应商认证。首版回调只唤醒查单，最终事实由可信原单查询确认；无回调则受限轮询并保留手动查单。产品、金额、币种、本人关联、原申请号、日期任一不符隔离审查。支付、退款、出单事实追加保存，不能用旧响应覆盖新事实。

当前日期字段为 `coverageStartDate/coverageEndDate`，不具备精确小时。供应商须明确日边界、时区、含首尾日与等待期；若要求小时保障则先版本化扩展合同和资格判断，不截断时间。改期/场地或项目变更重新评估适用范围；旧单记录不变，不把旧保单自动延长。首版不做自动批改；用户通过服务方批改或取消重购，旧单未知/退保未定时继续挡重复投保。外购保单与在线保单分别保留证据来源，由当前材料及当前赛期判定资格。

## 6. 迁移、恢复与实施

本轮准入和核对框架已使用Migration043，001—042保持冻结；后续真实供应商专用字段须继续追加迁移。旧单无准入快照标记 `LEGACY_REVIEW_REQUIRED`，保留查单、退保和文档读取，不回填“已审核”。开关关闭只阻断新投保，保留历史服务路由和未决提示。`RESTORE_QUARANTINE` 仍关闭一切对外调用；恢复先比对保单/退款事实及原号，再由受控流程解除隔离。监控成功出单时延、已付未出单数量、UNKNOWN 最长年龄、资格失效、回调验签失败、退保待核对、驱动配置不匹配；不把敏感身份作为指标标签。

拆包：①服务方合同/销售责任/产品证据与沙箱；②驱动、认证和商品准入，纯端口契约测试；③现有编排联调与错误恢复；④界面状态及外购回归；⑤受控真机小额投保、退保、对账演练及灰度开关。①不可由模拟测试替代；每包更新开发与验收状态，未通过生产门槛不对用户显示可购买。

## 7. 可测试验收

1. 无真实驱动或任一必要配置缺失时，新投保不可用，外购入口可用且不发网络请求。
2. A 组织会话无法读取或操作 B 组织保单；客户端改 provider/付款域名无效。
3. 未预审、资料过期、授权撤销及未具备投保关系的未成年人均被拒绝新单。
4. 不适用篮球赛事、年龄/地域不符、过期审核及同版本条款变更均不可售。
5. 报价过期、赛期/身份资料变化后旧报价不可购买。
6. 同幂等号同内容返回原单；不同内容冲突；并发购买只保留一个有效未决申请。
7. 请求发送后断网仍只查询原申请；查询空结果和重开预算不产生第二次申请。
8. 假回调、重放或跨订单事实不改变保单；乱序回调不让已付/已取消回退。
9. 已付款未出单不通过保障资格；出单事实不带匹配身份/日期/金额时隔离。
10. 取消与迟到出单交错仍保留事实并继续原单退保；退款未确认不显示已到账。
11. 赛事改期后原保单不可凭旧资格继续放行，外购保单同样重新核验。
12. PDF 非本人不可取，超限/伪造 PDF 被拒；日志与导出不含完整身份证。
13. 恢复隔离、旧租约迟到及驱动身份变更均不触发新单或错误覆盖。
14. 真机完成跳转、付款返回、查单、下载、退保全链路并与服务方逐单对账后，才可提生产验收。
