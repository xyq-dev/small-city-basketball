## 1. 管理员办赛的两种入口

两种入口汇入同一赛事、资格审核、名单冻结与排赛流程，不创建第二套比分或球队身份体系。

| 入口 | 操作与结果 | 保留的边界 |
| --- | --- | --- |
| 已确定参赛球队 | 选择机构已有球队，或批量录入受邀球队草稿；确认参赛意向，生成对应赛事、球队的邀请 | 录入队伍不等于球员已确认、资格通过或名单已冻结；不能要求所有球员先注册才能保存赛事草稿 |
| 公开招募球队 | 配置规程与报名条件，独立发布招募页；球队申请，主办方审核 | 招募页可在正式赛程生成前发布；不得将整个私有赛事或私有名册直接公开 |

主办方须具有对应机构和赛事权限；普通球员不因报名获得工作人员权限。批量导入须先预览、定位重复和错误，确认后可按原请求核对结果，不通过同名自动合并球队或个人。

### 8队分组接淘汰示例

1. 建草稿：名称、举办城市、场馆、主办机构、日期、联系人与公开介绍。
2. 录入或选择8队，绑定领队；向每队发送其专属报名邀请。
3. 设置参赛条件、每队人数、跨队规则、截止与替换规则、必传照片、身份资料、签署、保障与费用要求。
4. 选择A/B两组各4队、组内单循环、每组前二晋级；可配置种子队。正式分组以满足条件的冻结名单为输入。
5. 队员自行填写，领队核对进度并提交队伍名单；有权且符合独立审核要求的人员审核、退回补齐，最终锁定本届名单。
6. 抽签、设置场地时段与休息间隔、安排赛程、预览冲突、确认正式版本。
7. 配置工作人员，显式发布对外内容；记分与独立确认后推进晋级、季军赛和决赛，最后完赛归档。

完整模板：12场小组赛＋2场半决赛＋1场季军赛＋1场决赛＝16场。半决赛为A1对B2、B1对A2；胜者进入决赛，负者进入季军赛。关闭季军赛时为15场，并明确两个并列第三名的规则。8队全单循环为28场，不能标作16场。队数、名称、费用和时刻都是配置，示例不硬编码为全国默认。

现行代码没有季军赛；新增负者来源、赛果更正和后续比赛已开始后的处理须先补齐规则与契约。管理员录入便利性不意味着取消独立报名审核、赛果确认或直接伪造APPROVED状态。

## 2. 球员本人报名流程

以青锋队球员为例：打开本届青锋队邀请 → 登录并核对赛事及球队 → 本人填写并确认资料 → 上传本人照片 → 阅读对应版本规程并签署 → 资格预审 → 选择已有保单或在线投保 → 保障核验及其他必要条件检查 → 领队提交队伍名单 → 组委会最终审核 → 名单冻结。

首次提交不强制先付保险费；优先完成资格预审，减少资格不符后的无效购买。资格预审通过不等于最终可上场，保障有效性、必选费用、当前名单版本和最终审核仍须成立。上述顺序须在UI清楚呈现，允许保存草稿、补交、退回和恢复，关闭页面后不得丢失已确认的提交结果。

| 内容 | 要求 | 展示与存储 |
| --- | --- | --- |
| 姓名 | 本人填写真实姓名，确认用于本届资格核验 | 私有实名与对外展示名分开；公开范围另授权 |
| 身份证号码 | 本次实名报名流程必填；校验格式与重复参赛规则 | 格式校验不代表已完成实名核验；受保护存储、界面按权限脱敏，不进日志、海报或公开接口 |
| 本人照片 | **必传**，近期清晰正面单人照片，可用于核对相貌及经授权的宣传制作 | 不得用默认头像、队徽或他人照片代替；私有原图与公开宣传版本分离 |
| 球衣号码及其他参赛字段 | 按赛事规则填写和校验 | 历届名单保留当时快照，不被长期档案修改覆盖 |
| 规程及签署 | 显示当前规程与签署内容，记录本人确认及版本 | 不由领队代勾选本人确认，不以“已付款”代替签署 |
| 保障材料 | 复用已有保险或在实际保险服务方购买 | 材料、审核和出单状态分别保留，不把上传当成有效保障 |

本次“图片必传”指球员本人照片，**不自动追加身份证正反面照片或活体视频要求**。额外证件材料须有明确的资格核验用途和独立需求。个人资料可复用，但进入新赛事时须本人确认当前照片、规则和资料用途。

## 3. 必传照片、人工核对与宣传海报

### 上传与审核

- 球员可拍照或从相册选择，提供预览、裁剪、替换、上传进度及失败重试。本人照片必填，无照片只能保存草稿，不能提交正式报名。
- 提交时必须已有服务端确认、归属于本人和本届报名的有效照片记录；只选择本机文件、上传中或结果未知都不算上传成功。重试沿用既有恢复机制，不能重复创建报名或扣费。
- 首版接受JPEG/PNG，沿用现有单文件8 MiB上限；实施时由前后端同源校验类型、真实内容、大小和归属，生成安全显示版本并清除不必要的EXIF位置等元数据。此处未新增存储额度或服务承诺。
- 照片须能看清本人面部；过暗、严重遮挡、多人合照、队徽或疑似他人照片退回并说明原因。人工核对照片与参赛者相貌，记录核验人、时间和结论；本需求**不包含自动人脸识别、活体检测或人脸模板库**。
- 赛前检录人员只在被授权赛事或比赛范围内查看相应照片与最小名单信息；异常进入待复核，不能由照片相似度自动判定身份。
- 照片替换生成新版本，相关照片审核重新进行；已冻结名单中的照片保持原快照，通过受控更正后才更新当前比赛检录依据。

### 用途和授权

照片必须上传用于报名和相貌核对；**用于宣传海报的公开使用另行明确授权，不能默认勾选或把上传视作同意公开**。拒绝宣传用途不免除照片上传要求，也不单独导致参赛资格被拒；可使用无个人照片的球队或赛事海报。

授权页面说明使用主体、对应赛事、用途、展示渠道与撤回方式；保存本人选择、时间、条款版本和适用照片版本。换照片不能静默扩大原授权；公开前重新核验照片版本、审核状态和有效授权。

| 使用场景 | 使用内容与规则 |
| --- | --- |
| 私有资格审核／赛前检录 | 受限本人照片、姓名、号码及审核所需的最小字段；不向观众、普通队员或无权工作人员开放 |
| 球队阵容／球员宣传海报 | 本次经审核且授权有效的宣传照片、允许展示的姓名或昵称、号码、队徽、赛事信息 |
| 对阵／赛后／荣誉海报 | 按真实对阵和已确认赛果生成；个人照片仍逐人校验授权，不能因比赛公开就自动公开头像原图 |
| 未授权或授权失效 | 不生成新的个人照片海报；可生成不含该球员照片的版本，不用默认头像伪装照片已提交 |

原始照片不进入公开搜索或匿名接口。宣传素材使用独立派生文件和授权，URL不能携带身份证号码、私有原图地址、保单或写入令牌。生成和下载海报均需核验使用权限，记录所用照片、条款与赛事版本。

撤回宣传授权后停止新的生成与下载，并处理平台可控的公开资源；已经下载或被第三方转发的图片无法承诺全部追回，首次授权时明确说明。宣传撤回不自动删除有必要保留的私有审核材料；材料保留期限、到期清理与争议留存须在实施卡中明确，不能默认永久保存。检录导出和临时文件也纳入访问、留存和清理范围。

## 4. 保险与费用流程

| 路径 | 操作 | 通过依据 |
| --- | --- | --- |
| 已有外部保险 | 上传保单图片或PDF，填写实际保险机构、保单号、被保险人及保障期间 | 有权人员核对本人、篮球活动及赛事期间等要求；可退回补充，待审不显示已投保 |
| 在线购买 | 在已对接的实际保险服务方页面确认条款、保障期间、价格并付款，返回本平台查看进度 | 以服务方可验证的出单与保单状态为依据；前端跳转、付款截图或用户点“已付款”不算出单成功 |

保险费、赛事报名费和保证金分项展示、分别记录实际收款及退款责任主体；不设计成一个无法区分的“总费用”。本需求不授权平台自行承保或代收保费，不指定未签约的保险供应商、产品、价格或保障额度。

支付和保单各有状态：待付款、支付结果待核对、已付款；待出单、已出单、出单失败；另有保障待审核、通过、退回补充及失效。界面可展示“已付款待出单”，不得把其写成“报名成功”。支付成功但出单失败需有服务方查单、补出或退款跟进，不能静默要求重新付款。取消、退保与退款以实际产品和服务方规则处理，不自动作退款保证。

已有有效外部保单不强制重复购买。赛事改期或保障失效时重新核验受影响期间；不能沿用旧审核结果。未对接真实保险服务时保留外部保单审核入口，明确在线投保未开放，不放置可点击的假付款按钮。

最终参赛资格综合判断资料、必传照片及审核、本人确认、资格规则、保障、必选费用和有效名单；任何单项成功不能替代其他项。

## 5. 角色工作台与页面要求

| 页面／角色 | 必须呈现的内容 |
| --- | --- |
| 主办方创建向导 | 基本信息、球队来源、规程、资格／照片／保障要求、费用主体、人员、预览及发布检查；提示下一项阻塞 |
| 球队邀请页 | 明确赛事、球队、截止时间、邀请有效性；接受邀请不直接获得参赛资格 |
| 球员报名页 | 本人照片必填标识、姓名／身份证等表单、草稿恢复、上传失败和审核退回原因 |
| 保险选择与详情页 | 已有保险上传／在线购买、分别显示支付与出单及核验进度、失败处理入口 |
| 领队进度页 | 各球员的待填写、照片待补、资格预审、保单待补、审核、队伍提交和最终资格；默认不见完整身份证与保单 |
| 组委会审核／检录页 | 受限照片核对、必要实名资料、规则和保单审核、退回原因、当前版本和操作记录 |
| 海报制作页 | 真实赛事／球队／球员素材、逐人授权状态、预览和导出；不得带入身份证、保单、私有联系方式 |
| 球员报名结果页 | 明确当前阻塞、本人所属队伍、已通过的项目及最终结果；进入球队与本届报名分开显示 |

每页覆盖未登录、无权限、无数据、处理中、失败、退回、版本冲突、网络结果未知及换账号情形；320／390／430宽度和官方微信运行环境分别验收。缺少外部服务时继续完成独立可做的UI、私有资料和人工审核，但不以模拟付款代替真实保险验收。
