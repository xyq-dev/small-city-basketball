# 定位选城、附近发现与服务可预约性要求

更新：2026-10-30 Asia/Shanghai；任务：DOC004。性质：基于公开技术资料补充的产品与交互要求，**仅文档交付，未实施、未取得接口准入或第三方验收**。

上位依据：[全国平台与同城服务要求](../NATIONWIDE_LOCAL_REQUIREMENTS.md)第03、05、12章；界面入口：[UI规范](../UI_SPEC.md)；实际交付以[当前状态](../CURRENT_STATUS.md)为准。

## 1. 研究结论与本项目选择

本次实际读取了腾讯位置服务维护的定位与逆地址解析资料，以及百度地图小程序的逆地址解析、POI检索文档：

- 定位取得坐标；逆地址解析把坐标映射为地区和地标。两者是不同步骤，定位成功不保证已经可靠识别城市。[S1][S2][S3]
- 地点检索可以按城市进行，也可以围绕坐标和半径进行。百度官方小程序文档明确城市检索无需当前位置，因此手动选城可以作为独立可用路径。[S4]
- 定位接口涉及用户授权、声明及类目准入，坐标还要匹配地图服务；不能因为已有AppID或显示地图就宣称定位已开通。开发工具模拟的位置也不能替代真机结果。[S1]

**产品决定：先让用户选择浏览范围，点击需要定位的功能时再请求位置；找得到地点与能下单分开判断。** 以下页面、默认参数、排序和履约规则是本项目的设计选择，并非引用的官方强制界面，也不是对某个竞品全部流程的实测结论。

首发保留三条平等可达的路径：**定位当前城市／手动选择城市／先浏览全国**。不因拒绝定位阻止公开观赛、手动选城、查订单或按指定场馆预约。

## 2. 地域概念分别管理

| 概念 | 用途 | 不得替代的内容 |
| --- | --- | --- |
| 全国／同城／附近浏览范围 | 决定本次列表检索范围 | 不授予机构、赛事或个人资料权限 |
| 浏览城市 | 用户明确确认的内容频道，显示选择来源 | 不等于常驻城市、户籍或参赛资格 |
| 设备当前位置 | 用户按需授权后取得的短期查询起点 | 不等于服务地点、到场凭证或人员实时追踪 |
| 手动选择的地标 | 在拒绝定位时仍可指定搜索起点或目的地 | 不得显示成“我的当前位置” |
| 实际服务地点 | 用户在订单中确认的球场／比赛场馆及必要地址 | 不能被切城或新的GPS结果自动覆盖 |
| 服务覆盖范围 | 服务方审核通过的城市、区县、区域或半径及版本 | 不等于机构注册地址或地图POI附近范围 |

机构驻地、球队所在城市、球员常驻城市、赛事举办地保持原含义。高州可作为业务频道，石鼓作为下一级地区；地图返回的地级市、县级市、乡镇要映射到版本化内部地区ID，不能仅取一个名为city的字符串就将高州误归入另一个频道。同名地区使用完整上级路径区分。

## 3. 首次打开、再次进入与切城

### 3.1 首次打开

1. 立即显示可浏览的全国内容与“选择城市”入口；可用一张可关闭的选城引导卡，不先弹系统定位授权，不强制登录。
2. 提供“定位当前城市”“手动选择城市”“先浏览全国”。关闭引导等同先浏览全国；本次访问不反复弹出。
3. 点击定位后先说明“用于推荐本地赛事和服务，可随时手动切换”；按微信当前接口要求完成隐私说明及必要授权。登录、一般隐私说明同意、位置权限分别处理，不能相互替代。
4. 定位及解析成功后展示候选“高州 · 石鼓”，由用户确认使用；允许手动改选。不把定位结果自动写入个人档案。
5. 用户拒绝、取消、接口未开通、系统定位关闭、超时或解析失败时，仍留在可用页面，直接提供手动选城与全国入口。只有用户主动再次选择定位时才提供重新尝试或去设置入口，不循环索权。

### 3.2 再次进入与异地

- 优先恢复最近一次明确选择的浏览城市或全国范围，并标注“上次选择”；仅为恢复城市不调用位置接口。
- 同城和首页共享已确认的浏览城市，当前列表的类别、日期等筛选显示清楚。
- 用户主动刷新定位后若与已选城市不同，显示“当前浏览高州，定位到广州”，由用户选择“切换到广州”或“保留高州”。保留时不重复提示本次定位结果。
- 已选高州但当前位置在广州时，附近服务入口先说明起点差异，可明确切到广州，或在高州手动选择地标。不能把广州距离标在高州同城列表中而不说明。
- 从分享链接进入其他城市赛事时，直接按链接权限打开并显示举办城市；不自动改变浏览城市、不先强迫选城。
- 切城更换列表上下文和分页，从第一页重新读取；已创建订单、报名草稿、原操作编号和已确认的服务地点不丢失、不改写。

### 3.3 选择城市页

包含城市／区县搜索、最近选择、按行政层级浏览、定位入口、全国入口和当前选中项。推荐城市必须来自运营配置，不用虚构人气或供给数字。无本地服务的城市仍可浏览真实公开内容，并显式标注服务未开放。

手动选城不调用GPS；只保存城市／地区ID及选择来源等偏好。用户可清除最近选择。账号切换可以保留明确标注的设备级浏览城市，但不得沿用旧账号私有地址、订单地点或精确位置。

## 4. 附近发现与地图交互

### 查询起点与列表

- 顶部始终显示查询依据：“按高州筛选”“距当前位置约…公里”或“距石鼓文化体育中心约…公里”，不混用。
- 只选城市、没有可靠坐标时，不展示“距你500米”，不把城市中心当作本人位置。“距离最近”排序不可用，替代为地区、类别、日期和服务状态筛选。
- 允许按当前授权位置或手动选中的公开场馆／地标找附近。粗粒度位置只支持城市或大致区域推荐，不伪装成精确米级距离；位置精度不足以支持展示时提示选择地点或重新定位。
- 原型可提供1／3／5／10公里及全城筛选，默认取所选城市边界与搜索半径的交集；“全城”仅取消半径限制，不改变城市边界。起点在所选城市之外时先按3.2节选择切城或城内地标。跨城结果由用户显式选择邻近城市或扩大范围，并标注所属城市。无结果不静默扩大范围。
- 距离默认标“约…公里（直线）”；驾车／步行路线距离及耗时只在真实路线服务返回时展示，不能用直线距离估算通行时间。

### 地图与列表

列表作为首要入口；地图作为同一结果集的可选视图。选择标记同步对应卡片，返回列表保留筛选和滚动位置。拖动地图后提供“搜索此区域”，用户点击后才改查询范围，避免不停发请求。默认搜索所选城市与视口的交集；视口跨城时提供保留同城或明确扩大本次查询范围，展示结果所属地区。本次地图范围不自动写入浏览城市或订单。

场馆详情提供地址和导航入口。用户可复制地址或手动选择路线起点；不因本平台拿不到设备定位而阻止查看场馆。调用外部地图前明确目的地并按实际能力处理失败，服务端密钥不出现在导航链接。

## 5. 根据位置筛选服务与判断可预约

### 各种业务的匹配依据

| 业务 | 发现方式 | 可执行动作的条件 |
| --- | --- | --- |
| 赛事与观赛 | 已独立公开的赛事按举办地、日期和状态筛选 | 公开授权仍有效；报名另校验规程、名额和资格 |
| 固定球场 | 按场馆实际地址／坐标找附近，展示开放信息 | 经营方已核验并授予预约权，所选时隙、库存和开关有效 |
| 裁判、记分、摄影、直播、医务 | 按用户指定的比赛地点、项目和服务日期匹配 | 服务覆盖、必要资质、人员档期、接受条件及真实履约主体均成立 |
| 球员邀约、球队约赛 | 城市与场地、时间、角色、赛事条件 | 双方意向与档期、资格等分别核验；所在地不证明户籍或参赛资格 |

球员和人员卡片显示服务地区、项目及公开档期，不公开个人住宅或实时GPS，不用定位给球员自动签到或判定到场。

### 地图地点不是平台库存

地图检索到的球场只可在授权的数据使用范围内作为地点参考；在平台供给审核、经营方绑定、预约授权和库存完成前，不能显示“已入驻”“可预订”或代收费用。地图POI、场地实体与机构拥有的预约资源需做显式关联，不能凭同名自动合并或把同一球场创建为多份可售库存。

### 展示信息、供给能力与订单状态

每项显示服务主体、地点或覆盖区域、可用时间、真实费用和下一步；以下三个维度分别表达，不能合成一套互斥状态：

| 维度 | 页面表达 | 对应动作与限制 |
| --- | --- | --- |
| 地点信息 | 开放规则、地址；可能尚未入驻或没有平台预约授权 | 查看地点，不出售未知库存 |
| 供给能力 | 支持提交需求／需确认档期／可直接预约，或范围外／已满／下架 | 按真实能力显示提交需求、选择时段或不可用原因；“可预约”仅表示当前可尝试 |
| 本人的需求或订单 | 已提交、待服务方确认、已确认等现有业务状态 | 仅在实际创建后展示，按订单合同和权限读取；列表上的“需确认档期”不伪造一笔“待确认”订单 |

服务没有即时库存时可登记意向，但不承诺接单；需确认供给的流程沿用接单后付款规则。用户看到“可预约”不代表已取得时隙，确认结果以后端成功保留库存／档期并创建有效业务记录为准。

默认排序优先显示匹配项目、地区及所选时段的有效供给；有可比距离时可选按距离排序。人员服务按对实际服务地点的覆盖和档期匹配，不以人员实时位置排名。广告单独标识，不能绕过资格、服务覆盖或假称“最近”。

### 下单时重新核验

选择服务 → 确认实际场馆／服务地点 → 选择日期和时段 → 服务端重新核验供给状态、覆盖、档期／库存、条件和必要权限 → 按原订单合同创建或确认。

人在广州可以为高州的比赛预约覆盖高州的裁判；人在高州也不能预约不覆盖实际比赛地点的服务。浏览城市和GPS仅提供查找便利，最终判断以已确认的服务地点为准。

前端状态不是授权或库存凭证。下单、接单与地点／时间变更时按业务阶段重新检查；库存／档期保留与订单确认须处于同一受控并发流程，不能先检查空闲再无保护地创建。并发抢占仅允许有效容量内的请求成功；重复提交复用原操作编号，不能重复占位或预约；失败返回原因，超时按结果未知核对，保留与释放遵循原合同。条件失效不自动替换球场、改价、重复下单或转为另一城市。订单保存服务地点、覆盖规则版本和条款快照；服务方后续改覆盖不追溯改旧订单，确实无法履约则进入变更、取消或争议流程。

## 6. 异常、权限和位置有效期

下列为原型默认参数，属于本项目设计值，实施时集中配置并验证，不是微信或地图供应商的额度：单次定位体验超时8秒；设备位置仅在本次前台会话内短期使用，超过5分钟需重新确认或刷新，不能当实时位置。供应商实际超时、调用频率和可用精度另行核验。

| 情况 | 页面与恢复行为 |
| --- | --- |
| 用户拒绝定位／关闭系统定位 | 手动选城、指定地点或全国浏览；不循环请求 |
| 隐私授权未完成、接口准入／版本不支持 | 对应原因说明；手动路径不被阻塞，不借另一接口绕过拒绝 |
| 定位超时、网络失败、地图配额不足 | 结束加载，提供重试和手动输入；保留原浏览城市，缺信息不伪装为空供给 |
| 位置过旧或精度不足 | 标注查询依据，隐藏不可靠距离和排序；重新定位或选地标 |
| 城市解析不确定、县级市或边界识别有歧义 | 展示候选完整地区路径，由用户确认；不默认猜测 |
| 城市有内容但没有服务 | 继续看赛事，提供其他地区和需求入口，不显示假价格或库存 |
| 查询后服务停用、时隙被占用 | 下单前重查并拒绝失效请求，保留合理表单内容供改选 |
| 快速切城、切筛选、拖地图或返回页面 | 只接纳当前查询代次的结果；旧分页与迟到定位不覆盖新选择 |
| 退出、换账号、页面卸载或撤销位置权限 | 使相关在途操作失效并清掉设备坐标及私有地点缓存；取消尚未发送的旧操作 |
| 请求已发出而响应丢失 | 保留原命令编号和结果未知恢复，不能把已发请求说成已取消 |

仅当用户主动定位时读取位置；不为此功能开启后台持续定位、收集轨迹或定时跟踪。设备坐标不持久化到个人档案、分析日志、URL、错误报告或公开缓存；服务端若为本次检索临时处理，完成后不保留。缓存已公开且获授权使用的地点数据须遵循其来源与版本规则，不能缓存未公开地址。

订单中用户确认的实际服务场馆是履约信息，与临时设备位置分开保存和授权；其保留规则沿用或补入订单设计，不因为清理设备位置而删除历史订单。向地图方传递位置仅用于所选功能，按实际接入更新隐私说明。

## 8. 技术边界和实施顺序

- **优先实现不依赖定位凭据的选城闭环**：地区目录 → 手动选城／全国 → 已公开内容筛选 → 无供给状态。随后接入按需定位与解析，再补附近供给与服务地点复核；不让地图准入阻断可独立完成的部分。
- 先对现有公开目录、场地、预约、会话代次及原命令恢复做差异表，复用已批准能力。新地区目录、公开供给和位置检索接口须明确字段白名单、分页、范围与撤销规则；本文不变更现有API路径或枚举。
- 定位优先只取足够的城市／区域信息；是否可采用模糊定位取决于当前微信版本、主体类目、授权和实际解析能力。若不能满足，不静默升级精确定位；先提供手动选择或另行解释必要性。
- 地点数据保存坐标系和来源；微信地图展示与拟选腾讯位置服务优先按GCJ-02对齐，其他来源显式转换一次并测试。不能直接混用WGS84、GCJ-02、BD-09，或把经纬度顺序写反。[S1][S2][S3]
- 地图供应商接口只负责地图能力，平台自己的服务列表、授权、覆盖与库存由后端判断。超时／配额错误不能降级成默认可售；地理字段都视为外部输入。
- 查询上下文包含地区、中心点来源、范围、类别、日期、排序与代次；分页绑定一致上下文。切城重置分页，旧响应丢弃。坐标参与的个性化结果不进入公共共享缓存。
- 供应商选择、应用类目与接口准入、隐私声明、合法域名、账号Key类型、商用许可／配额和成本在接入卡核验。服务端密钥保留服务端；若SDK需客户端Key，必须使用相应受限Key并按供应商规则限制，不放服务端secret。无需重复索取已有AppID，也不把新凭据写入仓库。
