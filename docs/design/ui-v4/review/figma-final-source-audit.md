## 新版“我的”与现有代码的差异

1. 微信登录现有契约为已绑定应用账号登录。前端先请求capabilities，明确本次身份认证同意，再创建LOGIN challenge、调用wx.login，并将challengeId/state/code送服务端；成功后读取真实session。仅wx.login回调不能当作应用登录成功。
2. wechat-service只查询ACTIVE wechat_identities；不存在时抛WECHAT_BINDING_REQUIRED，要求先已有账号登录并明确绑定。**新用户直接微信开户尚非已实现能力**。
3. 邮箱注册由canRegisterParticipant决定；不能把微信优先设计解读为自动注册或新增球队/机构授权。微信绑定需当前账号密码再验证；解绑退出全部会话。
4. 现有account WXML把scb-nav设为user或loading时显示。新设计“游客也保留五导航”是明确新增前端显示交互，不是现有实现。其余页面权限门槛保持原样。
5. 主线account.load把capabilities读取失败折叠为enabled=false。新设计若区分“读取失败/明确未开放”，需少量新增前端展示状态，不新增API字段，不硬开能力。
6. 主线邮箱login没有本地空值拦截，用户后续要求可新增必填提示；保留服务端校验，密码不擅自trim。
7. 协议勾选不能替代绑定/解绑的独立确认。头像昵称由用户自主设置，不默认向微信索取或自动导入，也不收手机号、unionid。
8. 原账号页有大量二级功能：本人材料、各类预约/原订单、授权档案、角色/机构、撮合/派单/培训、赞助/经费、隐私客服/绑定注销等。新主视图不能只保留四格而删除旧有有权入口。
