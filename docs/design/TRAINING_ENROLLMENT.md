# 培训招生功能设计

> 状态：设计完成待实现。基线：`xyq-dev/small-city-basketball@ebc391e8bd0ec24c3301f64d6ae2f395245701cb`。本文中的表、接口、状态、页面与验收均为候选设计，不表示代码或测试已经存在。

## 1. 范围与现有系统边界

全国功能要求第 12 章将培训招生列为后置项目；本设计补齐篮球机构课程、班期、单次体验和有限课包，不改变赛事报名、参赛资格或赛事排名。

首期开放成年人单次课、固定日期短班；产品默认短班不超过 8 周、8 次课。随后开放经审核的青少年固定班；最后开放限定课程、场馆、有效期和次数的课包。上述首期规模是产品选择，不是法定阈值；“已成年”也不自动豁免该产品实际适用的培训监管。无长期储值、余额钱包、自动续费、跨机构通兑和转售课时。未取得真实供给的城市只接受意向登记，不能显示假库存或收款按钮。

已核对主干合同：

- `local-services.d.ts` 只有球场、裁判等服务，尚无 `COACH`；不能把教练伪装成裁判。新增教练档案并接入共享人员档期，是否扩展服务枚举需同步检查全部消费者。
- `trade.d.ts` 的来源仅有赛事费用/押金、同城预约和球员邀约。拟新增 `TRAINING_ENROLLMENT`，同步实现来源报价、支付、退款、结算和注销关口；禁止伪造 `LOCAL_BOOKING` 来收培训费。
- `youth-guardians.d.ts`、成年再同意与 `insurance.d.ts` 均绑定赛事的 `event/entry/member` 范围。培训必须新增真实培训主体范围的适配，不能创建假赛事或继承一次赛事授权。
- 迁移采用主干现有迁移之后的新编号，实施时统一分配；不改写既有迁移及历史合同。

## 2. 供给核验与排课

机构档案包含履约主体、登记及所在地要求的许可备案、收款与监管账户、经营场所、投诉联系人、合同模板、有效期和审核证据；教练包含身份、执教能力证明、审核范围、有效期、背景审查结论与证据访问权限。公开页仅展示允许公开的核验项目和有效期，不将平台审核描述为官方认证。机构管理员不能批准自己的资质。

每个班期绑定课程版本、年龄与能力范围、实际授课地址、主/助教、每次课起止时间、容量、收费和取消规则；场地使用权、容量、教练资格和必要安全配置审核通过后才能招生。限制取场地安全容量、师生配比、机构配置中的最小值；到期或暂停立即停止新报名，已售课程进入人工履约处置。规则配置保存城市、适用人群、生效日期、课时折算口径和审核人；课次数不等于监管课时数，不用 90 天替代自然月限制，也不能拆单绕过适用收费上限。

每次课独立占用球场与教练时段，含准备和离场缓冲；不得把数周课程伪造成一个同城预约时隙。沿用现有所有来源一致的锁顺序：相关机构 mutex 按 ID 排序 → `x12_calendar_lock()` → 资源及业务行。新增培训排课必须加入赛事、场地预约、人员服务、球员邀约的共同冲突查询及恢复流程。主教练即使以另一角色接单仍按真实人员 ID 查冲突。

固定班先验证并预留全部场次，再开启招生；开放课包只售经验证的可履约供给，购买不等于已预约任意未来场次。每次选课重新锁库存，售包上限受可用供给约束；不足时停售、提供替代或退款。教练、地点或时间实质变更生成新版本与逐人待确认状态，不能后台直接覆盖学员合同；拒绝者按适用规则退未履约费用。

## 3. 报名、支付与候补

主体分别为 `applicantUserId`（经办人）、`payerUserId`（付款人）、`learnerId`（学员）；未成年人另有已验证监护人。付款不能证明监护关系或授予查看健康信息的权利。首期一个报名一名学员、一个原支付人，不做拆单代付及多人拼单。

流程：选班 → 校验学员资格/必要授权 → 展示合同及逐课价格 → 临时锁位 → 创建同源报价与订单 → 支付核验 → 正式入班。监护审核未完成只保留申请，不占名额、不收钱。锁位默认 10 分钟且不超过报名截止/开课时间，由服务端时钟决定；免费课程也要显式确认条款并原子占位，不制造“已支付”记录。

可售数 = 容量 − 已确认席位 − 未过期锁位；固定班同时约束班额及每个场次，插班只售尚未授课且明确列出的场次。使用同一事务锁定、唯一有效报名约束及版本校验，禁止先查余量后无锁写入。过期释放由定时任务和读写时惰性清理共同完成。

回调必须验证渠道、金额、币种、订单来源版本及支付流水唯一性。即使渠道实际扣款早于截止，平台确认时锁位已释放且被占用，也不能挤走他人：进入 `PAID_UNALLOCATED`，告知“付款已收到，名额未确认”，优先原路退款或由用户主动同意仍有库存的替代。退款未知时保留负债和对账任务，不能显示退款成功。来源被取消、资质失效或授权撤回同样不得自动入班。

候补按服务端入列顺序、公示的资格规则产生限时邀约；用户点击后重新验资格并取得锁位，才进入支付。过期顺延，不自动扣费、不暗中跳队，人工例外必须有理由和审计。候补通知不承诺已获得席位。

## 4. 课程与报名状态

| 对象 | 候选状态与边界 |
| --- | --- |
| 课程 | `DRAFT → REVIEW_PENDING → PUBLISHED → SUSPENDED/ARCHIVED`；修改关键条件产生待审新版本，旧合同保留 |
| 班期 | `DRAFT → READY → ENROLLING → RUNNING → COMPLETED`；可到 `CANCELLED`，成班人数不足不得默认延期 |
| 场次 | `SCHEDULED → IN_PROGRESS → DELIVERED`；另有 `CHANGE_PENDING/CANCELLED`，取消不能产生授课消费 |
| 报名 | `APPLYING → ELIGIBLE → HOLDING → CONFIRMED → ACTIVE → COMPLETED`；分支 `WAITLISTED/EXPIRED/PAID_UNALLOCATED/CANCEL_REQUESTED/CANCELLED` |
| 锁位 | `HELD → CONSUMED/EXPIRED/RELEASED`，终态不可复活 |
| 课时权益 | `AVAILABLE → RESERVED → CONSUMED`；请假回到可预约或 `MAKEUP_DUE`，退款后 `REFUNDED`，纠错用冲正事件 |
| 消费确认 | `PROPOSED → REVIEWED → NOTICE_PENDING → OBJECTION_WINDOW → FINALIZED`；可到 `REJECTED/DISPUTED`。`FINALIZED` 区分本人确认与有效规则下流程到期，不伪造签名 |

争议、待退款、监护复核和恢复隔离作为独立旗标，不用单一报名状态吞掉财务或安全义务。班期完成不等于钱已结清；结算另受交易关口控制。

## 5. 青少年、签到与接送

拟新增培训学员及监护关系证据：授权明确机构、学员、班期/期限、用途、政策版本及撤回版本。用途分别处理参加培训、必要个人信息处理、健康/应急资料、宣传照片、公开档案、直播录像和接送安排；可选宣传授权不得作为报名条件。安全管理影像的处理依据、保管和访问与宣传同意分开核验，不因用户不授权宣传而缺失必要安全措施。现有赛事的 `PUBLICITY/PUBLIC_ARCHIVE/LIVE_RECORDING` 不自动扩展至培训。

首期不开放低龄儿童业务；青少年阶段按审核年龄段开放，适用范围及所在地要求先核验。学员满 18 岁时，要求本人完成身份/年龄证据和培训范围内再同意；此前监护授权不自动转成成年人授权，未完成时暂停后续必要数据处理和新增预约，由人工安排安全交接或退款，不删除已发生事实。

签到记录到场、操作者、时间及核验方式；授课记录实际教练、时间、内容和异常；消费记录另行确认。扫二维码只能找到本次记录，不能单凭二维码认定身份、扣课或交接儿童。工作人员结合已验证账户/授权名单及现场核验完成签到；失败时走人工复核并留痕，不让儿童自行离开。

接送人权限由有效监护人单独授予，限定学员、日期/场次和有效期；不得转授。签退须验证实际接送人、授权实时状态及工作人员，记录交接结果。临时变更由监护人通过已验证渠道确认；二维码丢失、陌生人取走截图或授权撤回均阻止交接。异常进入受限安全处置记录与紧急联系流程。教练只能看到本场必需的最少安全提示，不能下载全部证件、监护证明或健康档案。

## 6. 请假、补课、取消与退款

消费确认采用逐学员、逐课次流程：教练提交实际授课及拟消费权益 → 机构另一名具有复核权限的人核对签到、授课事实、请假/补课和价格快照 → 向成年学员本人或当前有效监护人送达消费明细。单人机构须由平台独立复核者处理，教练不能自审；付款人、接送人不因其身份取得消费确认权。复核前仅预留权益，既不能重复预约，也不能据此结算；驳回时释放或保留待补课权益。

查收页给出场次、实际授课、拟消费课时及金额、证据摘要和“确认本次消费”“提出异议”。提案默认应在下课后 24 小时内提交，复核及送达默认 48 小时内完成；这些是产品处理时限，超时进入运营待办，不能自动通过。有限异议期默认 72 小时，只在开售前采用的有效合同规则允许且明确告知时启用，保存规则版本与期限；从完整明细成功送达有权人的服务端时间起算，不能从开课、签到或教练提报时起算。送达失败、监护复核中、成年人再同意未完成或没有适用规则时，不启动倒计时，转人工联系。

本人确认可提前完成消费流程；无异议期满仅在送达证据、合同规则、无争议与资格条件均成立时标记 `FINALIZED/RULE_WINDOW_ELAPSED`，不得记为“学员已确认”、生成学员签名或将送达等同查收。主动确认记录为 `FINALIZED/USER_CONFIRMED`。两者均保留通知、操作者及版本。该窗口控制产品内部处理节奏，不关闭后续投诉及依法享有的救济；没有满足条件的有效确认不能让定时任务强行扣课。

异议提交与到期任务锁定同一消费及权益行；未解决异议立即标记 `DISPUTED`，冻结该课次对应金额的消费终结和结算，不影响无关课次正常履约。机构提交答复及证据，由未参与原授课/复核的平台争议处理者裁定平台内处置；处理者不能直接改钱。结论为维持、补课、调整或退款，财务调整仍经过独立提案与复核。已结算后收到有效异议则保留申诉与追偿/退款负债，不能删除原结算。纠错只追加引用原记录的调整/冲正、补课或退款事件；教练无权删授课事实，财务无权改签到，异议撤回也须记录主体及理由。每次调整重新计算权益余额并防止原课、补课和退款同时重复受益。

下单前固定合同版本，明确请假截止、补课次数/期限、缺席处理、机构取消、天气停课、改期和退费方式。请假获批保留原课时价值并建立补课权益；补课重新占位但不生成第二笔收费，原课与补课最多消费一次。未经批准的缺席也不能伪造“到场”；是否产生合同扣费须独立提案、依据和复核。到期不得静默清零有争议权益。

机构取消场次不记已授课、不扣课，用户选择补课或退款；延期、教练更换和更换远端场馆提供明确接受/拒绝路径。机构停业时冻结新招生与结算，逐单处理未履约权益，不把停业当学员违约。

订单冻结每次课净价、折扣分摊、赠课处理和费用组成。以分为单位，按原价权重分摊订单级折扣，取整余数按固定顺序分配，保证总和等于实付；退款不能把已上课按新单价重算。赠课若净价为零，退款金额为零但补课和履约义务仍有记录。保险等另购项目单列，不能混入培训净价。

可计算示例：4 次课原价 `[30000,20000,25000,25000]` 分，整单优惠后实付 `90000` 分，冻结分配 `[27000,18000,22500,22500]`。第 1 次已授课且确认消费 `27000`；第 2 次机构取消退款 `18000`；第 3 次批准请假保留补课 `22500`；第 4 次学员按本例“未上课无扣费”条款退出，新增退款 `22500`。因此 `90000 = 已消费27000 + 已退/应退40500 + 补课权益22500`。若第二次退款尚未知，新增申请只针对第 4 次，不重复申请已预留的 `18000`。这是产品示例，不能据此声称法定退款比例。

退款申请列明选中课次、原净价、已消费、已退、预留、拟扣款依据及附件。提案人与复核人分离；金额以服务端源数据重算，不能直接输入任意退款额绕过规则。未知退款保留预留并查询原请求；仅明确失败且允许重试时重试同一幂等键，不创建重复退款。结算以已履约、无争议、可结算余额及适用资金监管规则为前提，不把预收费全额立即结给机构。

| `training_enrollments` | 三方主体、班期、合同/报价哈希、状态、资格快照、version；同学员同班唯一有效报名 |
| `training_seat_holds/waitlist` | 学员、班期/场次、expiresAt、消费状态、候补顺序；终态不复活 |
| `training_attendance/delivery_records` | 到场/签退事件与实际授课事实分表；记录纠错引用，不覆盖历史 |
| `training_lesson_entitlements/consumptions` | 逐课净价快照、原课/补课关联、预留/消费/冲正；提报/复核人、送达证据、规则版本、异议截止、终结方式、争议及调整引用；每个权益唯一未冲正消费 |
| `training_change_requests/refund_allocations` | 变更前后版本、逐人选择、逐课金额、提案/复核、tradeRefundId及预留状态 |
| `training_command_receipts/audit/outbox` | commandId、actorId、请求哈希、结果引用、事件版本、投递重试；不记录明文令牌 |

候选读取：`GET /training/courses`、`GET /training/cohorts/:id`、`GET /training/me/enrollments`、`GET /training/enrollments/:id/ledger`。候选写入：`POST /training/providers/:id/reviews`、`POST /training/cohorts/:id/publish`、`POST /training/cohorts/:id/holds`、`POST /training/cohorts/:id/waitlist`、`POST /training/enrollments/:id/{confirm,leave,makeup,reschedule,cancel,refund-proposals}`、`POST /training/sessions/:id/{checkins,checkouts,delivery}`、`POST /training/consumptions/:id/{review,acknowledge,dispute,adjustment-proposals}`、`POST /training/guardian-grants` 与 `/:id/withdraw`、`POST /training/pickup-grants`。支付/退款复用扩展后的统一 trade 服务，不另造资金账本。

所有命令带 UUID `commandId`、`expectedVersion`、必要的 `acceptedTermsId`；同键同请求返回原结果，同键不同参数拒绝。权限按 actor 与机构/学员关系判断，不信任客户端传入角色。资格校验、席位、来源快照及 outbox 同事务；网络调用在事务外，以事件及补偿接续。客户端关闭页面不撤销已经验证的支付，重复回调不重复确认名额、消费或退款。

## 9. 权限、撤回、注销与恢复

学员/监护人访问自己的合同、必要学习记录；付款人访问付款和退款凭证，不因付款获得儿童健康或接送权限。机构管理员可经营本机构课程；教练只访问受派场次；财务查看最少账款信息；平台审核查看必要证据且留访问审计。跨机构读写、批量名单导出默认禁止，紧急访问必须有特定权限和原因。

儿童姓名、联系方式、出生日期、健康信息、监护关系与接送安排不进入公开名单、搜索、榜单、广告受众或通用日志。授权撤回立即提升 epoch，停掉相关公开内容、旧下载链接和后续使用；必要交易/争议记录按既有保留策略受限保存，不用“撤回”清空债务。

注销预检扩展培训依赖：未完成班次、未完成交接、退款未知、争议及未清权益必须给出逐项处置路径；仅结清并达到条件后关闭账号，不能级联删除账款。接入现有恢复隔离规则：恢复副本先隔离培训外发、招生、支付和接送令牌；重放注销/撤权事实、更新 epoch、核对供应商状态、对账并人工验收后按范围恢复。旧授权、旧二维码、旧席位锁不得随备份复活。

## 10. 验收清单（待开发后执行）

1. 未审核、过期机构或教练不能发布、锁位或收款；已售权益进入处置清单。
2. 同一最后席位并发提交，最多一人成功；失败者没有有效付款入口。
3. 同一学员重复请求不生成第二个有效报名；同幂等键改参被拒绝。
4. 锁位到期与支付回调竞态不会超售；有款无位进入明确补偿状态。
5. 伪造金额、币种、来源版本及重复渠道流水不能改变已确认结果。
6. 免费课只确认席位，不虚构支付；旧免费报名不得追溯变收费。
7. 候补邀约过期顺延；没有主动接受和支付不会自动扣费。
8. 排课与赛事、同城预约、球员邀约并发竞争同场地/人员，最多一方成功且无锁顺序倒置。
9. 固定班某场资源不足则不开放报名；课包选课重新校验容量。
10. 付款人不是监护人时，不能授权儿童参加、查看健康信息或修改接送人。
11. 赛事监护授权不能用于培训；拒绝宣传授权仍能报名。
12. 监护撤权、授权到期、成年再同意待补均实时影响后续动作且保留历史。
13. 分享二维码、已撤销接送授权或非当日授权不能完成交接；异常有人工路径。
14. 签到不直接扣课；未授课、机构取消不产生消费；补课与原课不能重复消费。
15. 逐课折扣分配含一分钱尾差仍精确等于实付，示例退款结果可重算。
16. 退款提案人不能自审；前端修改金额或重复提交不增加可退余额。
17. 退款超时保留预留、未知状态及查询记录；结算/注销不能掩盖该债务。
18. 学员拒绝实质改期/换教练有退款路径，机构不能覆盖原合同。
19. 未授权跨机构、普通教练、付款人请求儿童名单/证件均拒绝；日志无敏感明文。
20. 数据恢复后外发与凭证失效，已撤销授权和关闭账号不会恢复可用。
21. 正在争议的课时不能自动过期清零或结算；纠错可追溯原记录与复核人。
22. 青少年发布时验证所在地规则版本、课程跨度/课时/金额、资质及收款监管条件；不满足仅保留草稿。
23. 教练自审消费被拒绝；付款人/接送人不能代学员或监护人确认；无独立复核或送达失败时不开始异议倒计时、不结算。
24. 有效规则下无异议期满记录 `RULE_WINDOW_ELAPSED`，不生成学员签名；缺少规则、送达证据或主体资格时定时任务不自动终结。
25. 到期与异议并发只产生一致结果；未决异议冻结对应课次结算，已结算后的申诉保留债务及退款路径。
26. 纠错保留原授课和消费记录，追加调整需权限与独立复核；原课、补课、退款并发不会重复消费或重复返还。

## 11. 实施顺序与外部核验

| 阶段 | 交付和开放条件 |
| --- | --- |
| T0 基础 | 课程/教练模型、共享档期、权限、来源接口、UI原型；仅演示与内部审核 |
| T1 成人 | 单次课与固定短班、锁位、支付/退款闭环、候补、签到/授课分账；全部关键验收通过后按城市灰度 |
| T2 青少年 | 培训范围的监护、接送、成年再同意、敏感信息隔离、资质及资金监管核验；全部外部条件满足才开放 |
| T3 有限课包 | 按次权益、补课库存、尾差分配、消费争议与退费；禁止开放成长期储值 |

真实保险接口是相关依赖：培训覆盖项目、年龄、地点、日期、被保险人与退款规则须由承保方明确；现有赛事保单不能作为培训保障。投保/支付成功不等于出单成功；没有核验有效保单时不得展示“已保障”。保险是否为某班必需由适用条件与已公示规则决定，不能把篮球培训一概称为法定强制投保。
