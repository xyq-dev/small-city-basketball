## 按钮、跳转与业务约束

| 入口/操作 | 应有行为 |
| --- | --- |
| 赛事→抽签排赛 | 进入现有赛事排程路由，不另建比赛或计分数据源 |
| 日期、场地、视图 | 仅筛选显示；切换不得自动保存或丢弃dirty输入 |
| 点选/拖放 | 查看详情或形成本地安排，支持表单/键盘替代；仅当前可编辑DRAFT，正式/已开赛不开放拖动 |
| 开始时间 | 保留合法精度、时区、窗口验证；预计结束为占用时长推导的只读值，不独立编辑 |
| 外部占用 | 默认“场地已占用/不可移动”，不显示机构/培训/人员/订单来源或跳转；读取失败不能渲染成空闲 |
| 手机待排入口 | 打开待排列表/抽屉，选择后查看本地详情 |
| 服务端预演 | 沿用TMX01及补排/全稿两模式；dirty先明确保存/取消，不暗中保存或本地降级 |
| 对照→采用 | 显示原与建议/未排原因，仅改本地；全稿采用二次确认，取消不写入 |
| 保存草稿 | 复用原allocations、双版本及未知结果恢复，不改变发布状态 |
| 检查冲突 | 已保存输入才能校验，重新读取权威占用；无效、未排、越界或休息不足阻止发布 |
| 明确发布 | 仅最新完整校验通过后开放并另行确认；发布后本修订只读，改期沿原流程留历史 |

已整理加载、空白、读取失败、401失效、403无权限、409版本冲突、正式只读、dirty、完整/部分预演及发布确认11类状态。失效清旧建议，冲突保留输入、禁止旧版本盲重试；显式放弃重读与取消本地修改文案分开。所有球队、场次和时段是合成示例，不是运行数据或可排性证明。

## 数据与实现边界

目前API可读本稿fixtures/政策窗口及场地元数据，尚无完整外部占用时间轴端点。validate的external时间是受影响比赛区间，不是外部占用全区间；培训workspace/公开listing不能替代通用日历。

后续只读投影提案见[TMX研究](TMX_RESEARCH.md)：从服务端授权修订与场地集合取区间，复用原资源状态/buffer，排除本稿重复项，限制范围/数量，仅返回匿名court/time/readOnly、checkedAt及双版本。该提案尚未编写端点/契约/代码，须先审查冻结，再实现UI。不能复制第二套日历、将读取当预留、放宽机构边界或引入新记分计时。

逐场锁、多方案持久化、现场Now与裁判台不在本设计实现范围。
