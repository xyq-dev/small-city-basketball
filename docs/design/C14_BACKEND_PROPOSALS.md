# C14 待审后端方案（PROPOSAL，未实现）

2026-10-27 Asia/Shanghai。以下能力需要新增业务规则、数据结构、API或公开授权，按约定集中交 Codex 审查；审查通过前不改数据库、不加 Migration、不以前端过滤或硬编码替代服务端权限。不依赖这些方案的部分已在 C14 完成。

## 1. 公开赛事目录

沿用 [PUBLIC_EVENT_DIRECTORY](PUBLIC_EVENT_DIRECTORY.md)（C13 方案）。C14 在此之前提供了不扩大公开范围的过渡入口：公开赛事页分享卡片直达，本机“最近观看”只记录已打开的公开身份，撤销（404）后自动移除。手输43位编号降为“其他方式”，历史链接保持兼容。

## 2. 球员自建球队 / 自主加入球队

现状：球队属于机构，只有机构负责人/管理员可创建（`POST /teams`）；领队通过定向邀请（targetUserId）获得授权；球队成员是领队维护的姓名记录，不绑定球员账号。

- **业务规则（建议）**：参与者可申请创建“待认领球队”，必须挂靠一个机构并由该机构管理员批准后生效；或机构开启“开放建队”开关后直接生效。球员加入球队用“领队生成的一次性加入码”，加入后形成“成员-账号绑定”，领队可移除；绑定不改变既有本届报名快照。
- **数据模型**：`team_requests(id, org_id, requester_id, name, status PENDING|APPROVED|REJECTED, reviewed_by, reason)`；`team_member_bindings(team_id, member_id, user_id, status, created_at)`；`team_join_codes(id, team_id, code_hash, expires_at, max_uses, used_count, revoked_at)`。
- **API**：`POST /v1/orgs/:orgId/team-requests`、`POST .../team-requests/:id/review`；`POST /v1/orgs/:orgId/teams/:teamId/join-codes`、`POST /v1/team-join`（body code，仅已登录本人）。
- **权限**：审批同球队创建权限；加入码 hash 存储、限次限期、可撤销；不能凭姓名自动合并成员与账号。
- **验收**：未批准不可报名；加入码过期/撤销/超次拒绝；同一账号重复加入幂等；移除绑定不影响冻结名单；跨机构不可见。

## 3. 跨届球员数据 / 赛季数据榜

现状：仅单届“本届球员基础数据”（得分/犯规/名单场次，只计入独立确认的逐人赛果）；成员不绑定账号，跨届无法可靠归属同一人。

- **前置**：依赖方案2的成员-账号绑定（或现有球员预约资料的本人授权链路）。
- **规则**：只聚合“本人同意 + 主办方提名”的授权记录（沿用 C07 双边授权）；未采集项目继续显示“未统计”；按赛季（机构定义起止日期）聚合，不跨机构自动合并。
- **API**：`GET /v1/orgs/:orgId/seasons/:seasonId/player-statistics`（私有）；公开榜单需另行发布授权，与公开观赛同等白名单。
- **验收**：撤销授权后下一次读取即剔除；重开赛果退出聚合；sourceHash 绑定输入。

## 4. 关注提醒 / 订阅消息（外部依赖）

需要正式 AppID 的订阅消息模板、用户逐次授权与发送配额，属外部资质/凭据。规则草案：仅对公开赛事、用户主动订阅的“开赛/赛果确认”事件发送；不发送私有资料。未取得模板与凭据前，小程序“关注与消息”保持“规划说明”页，不显示假成功。

## 5. 小程序内上传/发布媒体、改期、分组与淘汰抽签

API 已存在（受控文件、改期命令、分组资格/同分/淘汰轮命令），但交互较重（文件选择与分片、改期冲突复检、抽签确认）。不需要新后端，属后续原生交互工作量；本轮在页面中明确“在Web赛事工作台完成”，列入交接，不作为永久方案。

> 状态更新（C16）：C15 已原生实现分组/淘汰、正式改期、媒体上传与发布；C16 补齐媒体预览、撤销后清除、时间标记与受信外链。本节不再是待办。其余各节的汇总与补充决策见 [C16 待审包](C16_PENDING_REVIEW.md)。

## 6. 支付、退款、分账（外部依赖）

需要真实商户号、证书与审查。小程序不调用 `requestPayment`，预约费用一律“支付未开放”，资金页面为规划说明。
