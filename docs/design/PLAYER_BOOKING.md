# C06 球员赛事预约：业务与界面规范

日期：2026-10-24（Asia/Shanghai）。这是本轮实现规范；实际验证、外部阻塞和未交付项须以任务卡及交接为准。

## 目标与边界

为球队领队提供球员筛选、单场/系列合作预约、逐场时间地点确认及履约记录；球员自主接受，平台审核服务资料、管理费率并保留审计。使用本项目既有 NestJS / PostgreSQL / React，不创建替代站点，不混用机构按届软件服务订单与球员预约订单。

整体模型为“合作总单 → 每位球员每场履约项”。SINGLE / MULTI / TOURNAMENT / SEASON / TIME_BLOCK共用逐场模型；未确定时间的条件场次是意向，不能显示已占档或已保证到场。

## 用户已确认的费用

- 试运营费率1000 basis points（10%），仅基于球员参赛服务费；交通/食宿需单列，不加收该服务费。
- 所有金额用整数人民币分，按每项计算服务费并汇总，展示参赛费、交通、平台服务费和总价。
- 订单保存费率、配置版本和球员报价快照。平台后续调价不追溯旧单；条件场次的预估也须保留原报价，变化需重新确认。
- 条件意向金额与确定场次金额分开，报价收入与实际收款收入分开。零实际收款不能记为已获利。
- 实际退款/结算只由已核验的支付能力驱动。当前既有微信按届软件收费不构成球员撮合收付/个人分账资质；不得复用为假支付。API须显式标注不可在线支付，资金记录保持未发生，履约记录不等于到账。

## 合作方式

| 类型 | 确定范围 | 关键交互 |
|---|---|---|
| 单场 | 一场、明确起止 | 选球员→代表球队→时间地点→费用→提交→球员确认 |
| 自选多场 | 多个明确日期 | 添加/删除逐场项、分别显示冲突和费用 |
| 整届赛事 | 已发布赛程＋条件晋级场次 | 明确“已确定”“待晋级”；晋级后激活并重新确认时间 |
| 赛季/长期 | 指定周期内已约场次 | 已确定安排与未来意向分开；逐场记录和退出 |
| 按时段 | 明确服务时间块 | 报到/开赛/结束、最多服务范围须在说明中明确 |

同一总单可包含不同球员。一个人的拒绝或一场取消，不自动终止其他合法履约项。总单状态来自子项，不以第一项代替整单。

## 身份、授权与资格

- 球员仅提交/更新自己的服务档案；平台operator审核资料。此审核不能称为实名认证、保险核验或职业等级认证。
- 广场仅展示获准上架的公开服务资料；个人草稿、驳回原因、订单、审计不向无关用户披露。
- 下单者必须具有当前球队授权；客户端orgId/teamId只是资源定位，不是授权凭据。
- 读取/写入与幂等重放均重新核验当前有效身份、球队授权和平台权限。跨机构共用同一真实球员身份做档期冲突检查。
- 预约不自动修改赛事报名快照，不绕过外援/户籍/报名截止/代表队限制。未完成资格或保险核验不得显示已核验。真实项目没有对应可核验来源时显式人工确认并保留责任说明，不能虚构通过。
- 仅成人入驻，当前成人确认是本人声明，不能伪装为身份证核验结果。

## 日程与变更

1. 统一保存有时区的时间，前端以Asia/Shanghai展示。报到≤开赛<结束。
2. 待接单固定场次短时保留，默认20分钟；超时释放。不能允许无限预约占满球员日历。
3. 已接受的固定场次阻止同一球员重叠预约，含必要交通缓冲；多项创建/激活/变更的锁必须原子提交，冲突不留半单。
4. 条件场次不持有具体档期。激活补齐时间地点并再次取得球员确认；不把“合作意向”改写成无条件到场承诺。
5. 改时间/地点须另一方明确同意；同意前原约定保留。接受新安排时重新核验冲突，保留变更理由和双方操作者。
6. 雨天、停电、弃权、伤病、临时退赛等按逐场变更/取消/争议处理，不能删除历史。

## 履约与异常

子项区分CONDITIONAL、REQUESTED、ACCEPTED、DECLINED、CANCELLED、EXPIRED、ARRIVED、COMPLETED、DISPUTED。实际到场、完成必须由有权限的参与方明确记录；未回复不等于已到场或已完成。争议阻断结算，完成服务记录不代表已收款。

取消保留原因、实际发生情况和金额快照；资料虚假、冒名、迟到爽约、途中伤病、教练未安排上场等需要证据，不将输赢/得分直接作为履约标准。更换球员须领队明确同意、重新核验新球员并重新接单。支付未接通时只记录费用与取消，不展示“退款成功”或承诺到账。

## UI原则与页面

深蓝#123C73、橙#F28C28，白底卡片、清晰中文信息层级、桌面/手机自适应；避免将生成的整张概念图当功能页面。合成照片只用于明确演示，真实档案无头像时显示姓名或球衣号码。

| 入口 | 主要内容 |
|---|---|
| 球员广场 | 搜索、位置/城市/日期筛选、单场报价、可约资料、接入状态 |
| 球员详情 | 服务档案、技术特点、报价/交通、可约窗口、预约入口 |
| 创建预约 | 授权球队、赛事、合作方式、逐场/条件项、费用与规则确认 |
| 我的预约 | 总单、逐场状态、双方可执行操作、报价/收款区别、变更记录 |
| 球员中心 | 本人入驻资料、档期、审核状态、收到的预约和接单 |
| 平台管理 | 审核队列、费率版本、预约统计、报价服务费/实际收款区分 |

API异常不能降级为Mock。Mock有固定醒目标识、仅使用合成数据，刷新行为如实说明；演示动作不写真实API，真实环境不能通过“模拟支付”进入PAID。所有按钮须对应真实行为或明确不可用原因。

## 验证重点

金额与报价快照、确定/条件场次、并发占档/全回滚、幂等与撤权、跨机构私单、本人/球员/领队/平台角色边界、变更双方确认、输入时区/边界、真实资金能力关闭，以及手机布局和原有路由回归。必须保留production的迁移集合、表集合与最小权限严格检查。
