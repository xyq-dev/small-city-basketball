## 2. 最小完整目标与边界

有赛事管理权限的主办方显式保存/发布排名规则，读取按当前有效确认赛果计算的单循环榜单；主动启用公开观赛链接后，匿名用户可看有限赛事资料、正式赛程、基础比分/时钟与排名。撤销后新读取立即404；重新启用必须新链接，旧链接永久失效。匿名页面不要求机构/个人登录。

仅支持P04已交付2–32队单回合ROUND_ROBIN。明确拒绝HEAD_TO_HEAD、胜率、弃权/处罚积分、净胜分封顶、分组/淘汰规则，不偷偷补默认FIBA规则。分享海报、微信小程序、专业统计、可靠离线、OBS grant/模板和真实云视频另卡。全P05及项目仍未结束。

Event保留SCHEDULED/RUNNING，不引入COMPLETED及自动冠军/晋级；“全部场次已确认”不等于完整赛事归档。P05-A原记分权限、状态机、时钟和正式计划保护保持；P05-B不改ScoringService业务。

## 3. 显式排名规则

- winPoints/lossPoints/drawPoints全部必填，整数0–1000，不预设2/1或其他分值。
- tiebreakers明确数组，可为空或从SCORE_DIFFERENCE、POINTS_FOR、WINS中取无重复有序子集。先比较积分降序，再按配置顺序比较全赛程累计指标降序；没有隐式兜底项。
- 保存新草稿追加不可变规则版本，用expectedEventVersion CAS更新当前指针；再单独显式发布所选rulesetId＋expectedEventVersion。首次发布后永久锁定，不允许通过新草稿改写同届已发布规则。
- 允许锁定前草稿预览，清楚标“草稿规则预览”；公开观赛启用必须已有正式锁定规则和一次正式赛程发布。
- 全部冻结球队入榜，字段played/wins/draws/losses/pointsFor/pointsAgainst/scoreDifference/leaguePoints。
- 所有配置项仍相同则共享名次，采用竞赛排名1,1,3。冻结来源顺序只稳定同名次展示，不能用内部ID、队名或随机排序决胜。
- 没有任何有效已确认比赛时rank=null、显示“尚无已确认赛果”，不把未开赛球队称为并列冠军。已有部分确认时按明确全赛程累计值暂列，未赛队显示未赛，不暗加胜率/场次补偿。
- 三队A胜B、B胜C、C胜A且所有配置指标相同必须共享第1；部分完赛或共同名次不自动宣布唯一冠军。

## 4. 唯一有效赛果与一致来源

仅match FINAL、scoring_state.requiresReconfirmation=false、latest_confirmation_id精确指向当前不可变确认且规则/统计/最后确认事件一致才计入。比分取确认记录，不取客户端或旧历史确认。重开后立即整场撤出，重确认后只计最新一次。

**不能用confirmation.sourceMatchVersion等于当前match.version或简单相差1判断有效。** CONFIRM本身递增版本，FINAL后合法staff修改也递增match/state版本但不改统计/事件，应保持既有赛果有效。确认后的最后事件须是对应CONFIRM_RESULT，原确认lastEventSeq/来源版本与命令收据相符；明确区分当前运行版本和正式来源版本。

按需计算，不建未实现的cache/outbox worker。当前最多32队/496场，单次批量SQL取所有match/state/current confirmation/必要last event与receipt，从同一语句快照做纯函数计算，不用N+1逐场读取，也不拼接并发重开前后的混合结果。freeze、规则、正式计划均不可变。若FINAL来源损坏/不一致，拒绝返回貌似正常的榜单；公开给无私密详情的不可用错误，不静默计入或掩盖异常。

结果包含rulesetVersion、sourceHash、asOf、confirmedMatchCount/totalMatchCount、isComplete和共享名次信息。isComplete仅全部正式比赛均有有效确认且总数大于0时true。相同业务来源hash稳定，serverTime/asOf不参与业务hash；clock显示按最新serverTime插值，不每秒写DB。

## 5. 权限、公开身份与有限字段

- 私有排名/规则读：OWNER/ADMIN或该event实际有效工作人员。只被分配某match的SCORER/RESULT_REVIEWER不会因此读整届私有排名。
- 规则草稿/发布、公开启用/撤销：OWNER/ADMIN或该event实际EVENT_MANAGER；当前会话、机构成员、Origin、CAS/白名单重新校验，global角色不代替分配。
- 公开单独使用服务端256bit随机publicEventId及每场publicMatchId；不得把内部org/event/match/entry/team/user ID当公开ID。每届public teamKey独立，不使跨赛事长期球队内部ID可关联。
- 每次撤销后再启用新建publication和全部新公开ID，不恢复旧身份。旧记录留审计，不能DELETE/复活。启用/撤销/规则发布与Event版本及audit同事务，失败整体回滚。
- 公开只白名单：赛事名称/日期/时区/已声明地点，冻结球队展示名/公开teamKey，正式轮次/场地/时间，基础球队比分/犯规/暂停/按节统计，raw clock＋serverTime，确认/待重确认状态，排名和公开规则摘要。
- 不返回roster/球员身份、工作人员、确认人、流水/收据、授权/lease/fence、内部IDs、邮箱/联系方式/保险/写凭据；不得spread私有Workbench或ScoreSnapshot后删几个字段冒充白名单。
- 未准备比赛score/clock为null，不能伪造已统计0；READY已初始化0须标已准备尚未开赛。球员未采集项显示未统计。
- 匿名读取不依赖Cookie，不因登录身份返回不同数据；前端专用public fetch使用credentials:omit，不触发私人会话失效处理或登录墙。
- 未知、已撤销、跨公开赛事的match ID、不活跃org或不可公开资源统一404。public游标只能含已公开键/时间及绑定scope，不把内部UUID塞进base64明文。

## 6. 接口与网页合同

精确DTO由API优先提交packages/contracts，消费者按该合同；以下路径行为已root裁定。

私有省略 `/v1/orgs/{orgId}`：

- GET `/events/{eventId}/standings`：event/规则草稿及锁状态、当前榜单/预览、当前公开publication及资源capabilities。
- PUT `/events/{eventId}/standings-rules`：expectedEventVersion及完整显式规则，追加不可变草稿并CAS。
- POST `/events/{eventId}/standings-rule-commands`：PUBLISH_STANDINGS_RULES、rulesetId、expectedEventVersion，正式锁定。
- POST `/events/{eventId}/public-viewing-commands`：ENABLE或DISABLE、expectedEventVersion。重复/旧请求明确409或重新读取已有状态，不重复产生有效链接。

公开 `/v1/public/events/{publicEventId}`：GET概要、GET `/schedule`分页、GET `/standings`、GET `/matches/{publicMatchId}`有限比赛快照。match必须属于该次public event publication，否则404。schedule默认20/最大100，游标绑定公开父身份和筛选；匿名无搜索目录。

前端私有 `/standings`、`/events/{eventId}/standings`；公开 `/watch/{publicEventId}`、`/watch/{publicEventId}/matches/{publicMatchId}`。匿名路径从RuntimeApp入口独立分流，不初始化私人会话/机构请求，不嵌套BrowserRouter或破坏原邀请fragment/Hashchange/Mock工作台。公开→机构工作台可整页导航，不能保留另一公开ID的旧资料。

公开页面轮询显示最后更新和陈旧/离线提示，时钟只扣一次。404撤销/失效后清除旧内容；不能承诺无推送时所有已打开页零延迟消失。网络失败可保留最后快照但标陈旧，不把故障当0分。世代/版本及卸载保护防旧响应覆盖新链接/比分。所有select/带初值textarea显式稳定可访问名称，浏览器精确匹配不能靠jsdom推定。

## 7. 数据、锁与迁移

私有操作沿actor/session→org/member→Event UPDATE→新规则/publication/映射；规则/公开写从入口Event UPDATE，不在读锁后升级。P05确认/重开Event SHARE因此自然串行。公开先解析公开身份，再按org→event→publication取锁并重查当前有效性，撤销提交后新请求立即拒绝；数据来源单SQL语句快照。公开GET不更新访问计数或触发记分，不占org_schedule_mutex。

不新增依赖、第三方追踪、公开上传或付费服务。当前规模限制与无公开SSE/缓存/CDN的边界写文档，不能承诺DDoS或生产容量已验收。
