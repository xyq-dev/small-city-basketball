## 3. 显式规则与状态

规则版本隶属event，管理者用expectedEventVersion CAS追加新规则，首次READY后该赛事规则永久锁定。必须显式填写，不默认FIBA：

- regulationPeriods整数1–8；periodDurationSeconds整数1–3600；allowedScoreValues为[1,2,3]非空无重复子集。
- tiePolicy为ALLOW_DRAW或OVERTIME；OVERTIME时overtimeDurationSeconds整数1–1800，ALLOW_DRAW时为null。
- 犯规和暂停只累计球队当节/全场次数，不暗设罚球/剩余暂停配额。所有统计正整数；SCORE须在允许分值中，FOUL/TIMEOUT每次为1。

比赛 `SCHEDULED → READY → LIVE → PENDING_CONFIRMATION → FINAL`。

- PREPARE_MATCH：当前管理权限；已有正式冻结名单、规则及至少一个有效SCORER分配；绑定并锁定规则，初始化第1节/剩余节长/暂停时钟。
- START_MATCH：显式SCORER主写，READY进入LIVE，时钟仍暂停。首次比赛LIVE使event从SCHEDULED进入RUNNING，同事务CAS/审计。后续场次允许event RUNNING。
- LIVE只有显式CLOCK_START才走时；CLOCK_PAUSE保存服务器计算的剩余值，CLOCK_SET必填理由且范围0至本节节长。
- NEXT_PERIOD：时钟停止且有效剩余为0，未完成常规节时进入下一常规节。START_OVERTIME：已完成常规节/前一加时、有效剩余0且暂停、平分且tiePolicy OVERTIME，进入新加时。
- END_MATCH：末常规节或加时有效剩余0，时钟暂停；OVERTIME要求分数不相等。进入PENDING_CONFIRMATION，时钟固定0。不得自动FINAL，不允许提前结束或弃权捷径。
- FINAL仅管理者REOPEN_RESULT且理由必填回PENDING_CONFIRMATION；保留原正式结果，标记待重确认，不回LIVE。待确认只允许有理由的统计修正及确认，不继续普通记分或时钟。OVERTIME规则下更正形成平局时拒绝确认，保持待处理；本卡不支持回LIVE补加时，不能伪造赢家。
- 本卡不自动COMPLETED整个赛事，不能凭全部FINAL推定正式排名及全流程完成。

## 4. 权限与独立性

所有操作先执行当前会话、org成员有效性、资源归属、Origin/输入白名单。全局EVENT_MANAGER/SCORER角色不等于实际分配；球队grant独立且不授予后台权限。

- 规则、准备、场次人员管理、重开：OWNER/ADMIN或该event实际有效EVENT_MANAGER。
- 写分和时钟：必须该match显式有效SCORER分配及当前org成员；OWNER/ADMIN也不自动获得写分。场次人员角色SCORER或RESULT_REVIEWER，状态ACTIVE/DISABLED；指定现有有效org成员，允许没有EventStaff的最小权限场次人员。
- 确认：OWNER/ADMIN、该event实际EVENT_MANAGER或该match有效RESULT_REVIEWER。**任何历史实际写分/时钟/开始/结束/修正者、当前主写者及当前任一参赛Team的有效领队都不可确认，OWNER无例外。**撤权、撤销事件和换租约不会洗掉历史参与。PREPARE、分配、租约、重开本身不算实际记分。
- 场次人员撤权锁match并令该人员租约失效。确认时锁排序后的双方Team再查当前grant，防领队激活与确认竞态；使用与P03一致的Team锁序。
- 只读：OWNER/ADMIN、该event任何实际工作人员、该match有效工作人员。仅场次授权者可读本场及其绑定规则，不能读取整赛事私有资料。所有DTO给资源capabilities，后端再次判断。

## 5. 主写租约、版本及命令

- 每match一个主写租约，TTL30秒，客户端10秒续约；绑定session、内存中每tab独立clientInstanceId、随机leaseId及单调递增fencingToken。刷新页面生成新tab identity，等待旧租约失效；不借localStorage/sessionStorage持久控制凭据。
- 未过期且同绑定的acquire可返回既有租约；其他端409。过期renew/release不能复活或释放新租约；每次新持有者递增fence。心跳不递增matchVersion。租约过期不自动暂停真实比赛时钟。
- 命令含commandId(UUID)、expectedVersion、type、payload、capturedAt，以及写分所需control{leaseId,fencingToken,clientInstanceId}。管理命令不伪造租约；服务器定义允许字段和每类型输入，客户端不能提交绝对比分、actor、seq或双方ID。
- 当前授权与动作权限先于幂等查重。以org/actor/match/commandId定位收据，同ID同规范内容hash返回原receipt及**当前**snapshot，appliedVersion与currentVersion区分；同ID不同内容409。历史成功重放不会再次写分，当前已撤权者也不能重放读取。
- 新命令验证状态、主写租约/fence、match CAS；单事务追加事件、更新projection及match status/version、写receipt和audit。任何失败整体回滚。已接受幂等重放可在原lease过期后返回原收据，但不能因此接受新命令。
- 命令至少覆盖PREPARE_MATCH、START_MATCH、RECORD_STAT、ADD_CORRECTION、VOID_STAT、REPLACE_STAT、CLOCK_START/PAUSE/SET、NEXT_PERIOD、START_OVERTIME、END_MATCH、CONFIRM_RESULT、REOPEN_RESULT；准确DTO由API先提交。更正/撤销/替换必填理由，撤销仅指本match仍有效SCORE/FOUL/TIMEOUT事件，拒绝重复撤销与跨match目标；替换保留原统计kind及period。补录允许指定已有period及合法统计值。原事件永不覆盖/删除。
- matchVersion对每个业务变化递增；分配变化若已存在projection也须保持sourceVersion一致。clockVersion只随时钟/节次动作递增；追加事件seq有唯一且连续来源。确认前按事件重放校验投影，不能信客户端绝对比分。

## 6. 时钟、快照及未知结果恢复

时钟保存period、remainingMs、running、anchorServerTime、clockVersion，使用取锁后的DB clock_timestamp单次时间，不用事务起点now；响应带serverTime，客户端按锚点插值，显示最低0，不每秒写库、不以客户capturedAt排序。服务重启后从同一锚点继续计算。剩余0不自动改变比赛状态或产生正式结果。

私有ScoreSnapshot统一包含match/event身份、版本、双方冻结展示名、比分/基础计数、规则摘要、时钟/serverTime、最新确认及待重确认标记；不含lease/session/写凭据、联系方式或身份/保险材料。工作台可包含独立受控Control DTO。该快照为后续只读观赛/OBS投影的数据基础，首卡不开放匿名或称已接OBS。

前端仅收到服务器成功ack后更新权威比分，不乐观加分。网络断开停止新写；超时/5xx/连接断开不等于命令失败，保留原envelope/commandId，显示“结果待核对”，先查当前receipt与snapshot。receipt读取在match读锁保护下等待已有写事务完成。找不到不代表已永远失败；重发必须保持完全相同命令及当前有效的相同控制/版本条件，否则人工核对后恢复，不能自动换ID重复加分。页面销毁/进程崩溃不承诺未持久命令恢复；重进先拉权威快照并重新取得控制。

确认记录不可变，包含confirmingUser、规则版本、精确sourceMatchVersion/lastEventSeq及比分/基础统计。确认当前版本后match FINAL；重开后旧确认保留且不作为当前有效赛果，新确认生成新记录。

## 7. 事务、数据库及接口责任

独立ScoringService/provider/controller复用ApplicationService鉴权，不改Registration/Scheduling业务。新增迁移004，保存版本化规则、match staff、状态projection、lease/fence、append事件、命令收据和不可变确认，使用复合org/event/match FK、check/unique及不可变保护。

基础锁序：actor/session → org → membership → event → eventStaff → match → matchStaff → lease → scoring state/events/receipt/audit。PREPARE锁规则/首次START修改event时必须从入口取event UPDATE，不能SHARE后升级造成两场死锁。确认在match后按Team ID排序取UPDATE，再检查领队grant；不得与P03建立反向环。读/lease/命令的授权撤销竞争也要用当前锁证明。管理员准备与首场开始不得覆盖并发Event版本。

私有接口统一 `/v1/orgs/{orgId}`：

- GET `/scoring-matches`：SQL过滤当前用户可见的场次，分页默认20/最多100，游标绑定org/user/event/status；不放宽P04赛事级matches权限。
- GET `/events/{eventId}/scoring`、PUT `/events/{eventId}/scoring-rules`：前者赛事工作人员/管理者可读；后者显式规则+expectedEventVersion，返回当前规则及锁状态。
- GET `/matches/{matchId}/scoring`：workbench；PUT `/matches/{matchId}/staff/{userId}`：角色/状态+expectedMatchVersion。
- POST `/matches/{matchId}/scorekeeper-lease`、POST `/.../renew`、DELETE `/...`：严格匹配control。
- POST `/matches/{matchId}/commands`、GET `/matches/{matchId}/commands/{commandId}`：统一命令/收据。CONFIRM/REOPEN本卡也走命令，现有总设计的独立endpoint视为后续兼容目标，不同时发明两份实现。
- GET `/matches/{matchId}/scoring-events`及`/matches/{matchId}/result-confirmations`：分别seq正序、sourceMatchVersion/id正序完整分页读取事件/确认历史，当前本场读取权限，游标绑定org/user/match。receipt查无404 COMMAND_NOT_FOUND，保持未知结果待核对。
- GET `/matches/{matchId}/snapshot`：私有无凭据快照。按需定期拉取，不假称已实现SSE/outbox或公开推送。

精确DTO、错误码及响应以本卡裁决后的packages/contracts为单一来源。规则、无效命令422；隐藏资源404；CAS、租约、幂等内容/状态冲突409；可见但无动作权限403。不得泄露其他机构或无权场次。
