## 目标与边界

获授权机构人员能在现有正式赛程调整未开赛单场的场地或开赛时间，必填原因，实时复检同机构跨赛事场地/球队占用与本届休息/日期间隔。比赛仍以`published_matches`为唯一当前安排；原publication/revision/fixtures/hash保持原始只读发布快照，改期历史不可变。原计分、名单、排名、公开身份、Overlay授权和时钟不复制、不重置。

- Event仅SCHEDULED/RUNNING；单场仅SCHEDULED/READY且无START_MATCH历史。LIVE、PENDING_CONFIRMATION、FINAL、重开后场次、POSTPONED/CANCELLED及已关闭赛事拒绝。
- 仅改court/start；沿用原policy时长、Court窗口、赛事日期、休息分钟、最小本地日期差及Asia/Shanghai语义，不扩窗口、不换对阵、不改名单、不批量改期。
- 同Court改时保留原courtName；换Court采用当时名称。无实际场地/时间变动409 RESCHEDULE_UNCHANGED，不能空写版本/历史。
- READY保留状态、所有比分/节次/事件/receipt/clock anchor/clockVersion/rules/lease/fence，只同步scoring_states.source_version与Match.version。旧版本写入必须冲突，不能自动重放。
- 手机/桌面交互显示当前正式安排、改期原因/历史、只读能力；版本冲突或响应未知先显式读取核对，不能盲目重复提交。原发布历史仍展示原计划。

## 冻结接口

前缀`/v1/orgs/{orgId}`，成功均200标准data envelope/no-store。GET `/matches/{matchId}/rescheduling`与POST `/matches/{matchId}/reschedule-commands`。POST仅接受：

```ts
{type:'RESCHEDULE',expectedEventVersion:number,expectedMatchVersion:number,courtId:string,startsAt:string,reason:string}
```

版本正整数、start带明确offset的有效ISO、reason trim后1–500。两入口返回`MatchReschedulingData`：`{event:EventData,match:ScheduledMatchData,policy:SchedulePolicy,history:MatchRescheduleRecord[],historyLimit:20,historyTruncated:boolean,capabilities:{canReschedule:boolean}}`。历史最近20条、LIMIT21判断截断，不伪造历史翻页。`MatchRescheduleRecord={id,fromMatchVersion,toMatchVersion,from:MatchReschedulePlan,to:MatchReschedulePlan,reason,createdAt}`，`MatchReschedulePlan={courtId,courtName,startsAt,endsAt}`。

读沿用本event实际工作人员/机构管理员；写仅OWNER/ADMIN或本event实际EVENT_MANAGER。单场SCORER/球队grant/未分配全局role不授改期权。Origin、会话当前有效性、机构/资源归属与能力由服务端每次重查。

## 数据、锁与审查裁定

独立只读源审查已确认需要新增`007_p04_match_rescheduling.sql`，001–006不能改。新增append-only `match_reschedules`（第40张manifest表），记录旧/新计划、旧/新Event和Match版本、原因/主体/时间和当前事务标识。精确历史证明才允许修改比赛计划及预约必要列；禁止删除/身份替换；deferred guard拒绝孤立历史、缺失/错误Court或两Team预约及投影版本不一致，既有排他约束保持。runtime仅新增必要列UPDATE和历史SELECT/INSERT；恢复/就绪/重启指纹同步40表及7迁移。

锁序复用session/user→org/member→org_schedule_mutex→Event UPDATE→Match UPDATE→必要projection/Court稳定排序。与发布、另一场改期、Court停用串行；PREPARE/START通过Event/Match锁竞争，重读状态与CAS。授权、冲突复检、不可变历史、当前match/三预约、Event/Match/已有projection版本及audit同事务，失败全回滚。

冲突输入由本event全部当前published_matches重建并替换目标；外部预约排除整份本event publication，本届内部冲突使用当前fixtures，不能取原发布的旧时间。仅目标相关冲突阻止此操作，其他过去场地已停用不误阻；跨event提示不得暴露无权资源详情。改期导致排序变化，私有/公开赛程旧分页游标须失效，防止漏/重场次。
