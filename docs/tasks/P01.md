## 目标

主办方能在演示环境中完成“查看工作总览→查看赛事列表→创建草稿→进入详情→编辑草稿”。让页面流程可运行，为后续真实 API 保留替换入口。

根 `AGENTS.md`、[当前状态](../CURRENT_STATUS.md)、[UI规范](../UI_SPEC.md)中的 P01、[接口契约](../API_CONTRACTS.md)中的 P01。按需参考[机构后台设计图](../design/03-organizer-dashboard.png)，不重复全面分析整个平台。

## 允许范围

- 创建 `apps/admin` 的 React + Vite + TypeScript 应用及必要根安装配置、依赖锁、启动说明。
- 实现四页、路由与共享布局、基本表单校验、Mock repository/service、明确的演示数据提示。
- 为 P01 增加合理构建、类型检查和关键交互验证。
- 更新本任务卡与[交接记录](../handoffs/P01.md)；汇总交由集成人更新。

共享根配置、依赖锁由 P01 的唯一负责人维护。只有真正需要时才建立工作区配置，不为未来模块生成空工程。

## 禁止范围

不实现真实登录授权、数据库、支付退款、保险销售、抽签算法、正式记分、视频推流或 OBS 远程控制；不修改其他项目或不相关设计文件；不制造“已上线”状态。

## 最小页面与字段

1. 工作总览：示例赛事、待办、今日比赛；未接通的菜单有明确占位说明，不使用失效按钮假装可操作。
2. 赛事列表：列表/空状态、名称或状态筛选、进入创建与详情。
3. 创建赛事：`name`、`startDate`、`endDate`、`timezone`（默认 `Asia/Shanghai`）、`venueName`、`format`；必填和开始/结束日期校验。
4. 赛事详情：展示草稿资料，允许编辑与返回列表；创建仅生成 `DRAFT`。`format` 使用 `ROUND_ROBIN / GROUP_KNOCKOUT / SINGLE_ELIMINATION`。

P01 不实现发布与报名状态流转。Mock 通过统一服务入口使用；默认内存保存，页面清楚提示“本次演示数据，刷新重置”，禁止静默采集真实人员资料。
