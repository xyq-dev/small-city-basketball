# 球员赛事预约使用说明（C06）

本轮为既有项目新增预约与履约模块。代码和UI在任务分支；不是正式站点上线公告。实际验证与限制见 [C06交接](handoffs/C06.md)。

## 入口

| 页面 | 路由 | 用途 |
|---|---|---|
| 球员广场 | `/players` | 位置/姓名/地区/日期筛选及报价排序 |
| 球员详情 | `/players/:profileId` | 服务介绍、档期、交通食宿及参赛报价 |
| 创建预约 | `/player-bookings/new?playerId=:profileId` | 单场、多场、整届、赛季、时段；支持多人和条件场次 |
| 我的预约 | `/player-bookings` | 我发出/收到的合作，按状态筛选与手动刷新 |
| 总预约详情 | `/player-bookings/:orderId` | 逐人逐场接单、变更、取消、到场与服务完成记录 |
| 球员中心 | `/player-center` | 本人入驻资料、可约时间与收到的预约 |
| 平台运营 | `/player-bookings-admin` | 仅实际platform operator可审核资料、改费率及处理争议 |

机构工作台有“球员预约”入口。个人账号没有球队也可进入球员中心申请入驻；没有当前球队授权不能发起球队预约。机构管理员不是平台operator。

## 演示与真实API

- `VITE_DATA_MODE=mock` 下运行现有 `npm run dev` 可使用合成数据演示；顶部明确显示演示标记，支持领队/球员/平台体验切换。刷新整页会重置，不发生资金、不联系任何真实球员。
- API模式复用既有登录会话、球队授权和PostgreSQL。接口失败显示真实错误，不补演示球员。
- 当前实时短信/微信推送未接通；收到的预约可通过页面“刷新预约”读取。编辑资料/未保存运营设置时限制刷新，避免丢失输入。
- 原有赛事页面按原流程工作；预约页面按需加载，避免把预约样式与演示状态加载到其他业务中。

## 完整预约操作

1. 球员在本人账号提交名称、位置、身高、服务区域、说明、参赛/交通/食宿报价和可约窗口，声明本人已满18周岁。
2. 独立平台operator审核服务资料。审核是入驻资料审核，不等于实名、实力、保险或赛事参赛资格认证。
3. 有球队授权者选择球员、合作范围及赛事，逐场补齐报到/开赛/结束/地点。可以在一个总单选择多位球员。
4. 固定项提交后短时保留20分钟等待球员确认；各场结束后另保留30分钟交通缓冲。冲突由服务端与数据库共同保护。条件意向不占档，触发后补齐实际安排并重新请求球员确认。
5. 页面分别展示确定场次报价与条件意向预计。参赛服务费300元、10%平台费30元、交通食宿0元时，确定报价330元。
6. 下单带领队审阅的档案/费率版本；变化返回`QUOTE_CHANGED`，保留表单并由用户主动读取最新报价、重新确认。不能悄悄重报价再提交。
7. 球员在详情自主接受或拒绝。时间/地点变更由交易另一方确认，同队第二领队不能代球员同意。取消只影响对应球员对应场次。
8. 到场是球员本人声明；达到服务结束时间且有到场记录后，由授权球队方确认完成。当前不是GPS/二维码核验。
9. 争议保留相应档期、阻断结算；独立平台operator填写原因后可取消、恢复或在已有到场且服务结束时确认完成记录。操作保留原/新约定与审计历史。

## 资格和资金边界

- 订单显式标注`DECLARED_NOT_VERIFIED`：资格只是双方声明，仍需主办方核验。预约不添加或修改冻结报名名单，不用姓名猜测账号与原球员身份。系统能确认的同赛事跨队合作会阻断；这不是完整的人证匹配。
- 已关联正式比赛的时间/地点及状态变动需要重新确认，不把过期安排当作已经匹配。实际资格/保单检查继续由原报名流程及主办方负责。
- 撮合支付和个人分账尚未配置，`paymentAvailable=false`、`UNAVAILABLE/BLOCKED`；所有实收/退款到账/已结算始终为0。完成服务记录不会产生付款。
- 当前支持的是预约报价/履约记录，不支持通过页面自行标记已付款。既有机构按届软件收费与个人球员服务订单保持分离。
- 后续真实资金接入需支付渠道审核、资格/人档关联、交易通知和资金退款/分账/对账的独立验证；不能仅打开一个按钮上线。
- 付费档期保留、自动周期扣费、用人需求公开招募、自动替补推荐和真实视频/实名核验不在本次已交付能力中；临时换人需明确取消原项并另行预约新球员。
