# 后台对象存储配置（COS02）

入口：业务后台「系统设置 → 对象存储」，路径 `/system/storage`。仅有效平台运维账号可以操作，机构负责人/机构管理员不会自动取得平台权限。已有平台身份沿用原离线维护流程，不通过网页自行授予角色。

## 部署前准备

本功能新增 `051_platform_storage_settings.sql`，必须先在隔离环境验收完整迁移链、备份及恢复，再按正式升级流程执行。001—050保持原文。源码和CI结果不代表生产已部署或真实COS已联调。

后端将访问凭据加密保存在数据库；独立加密根密钥必须放在数据库及数据库备份之外，由部署人员一次性准备。不要把它填在网页、提交Git、打印到日志或随数据库归档。

1. 在主机准备已有的、root所有且0700的私有 provider 目录；不要使用站点或数据库目录。
2. 使用主机维护身份执行 `node ops/setup/storage-config-key.mjs /absolute/private/provider-secret-directory`。该命令只创建 `storage_config_key`，使用随机32字节的64位十六进制内容，owner/group 10001、0400；已有合法文件保留、不覆盖、不输出密钥。所有权/路径/符号链接不符合要求时失败关闭。
3. 使用已有生产Compose加 `ops/templates/compose.storage-settings.yaml`，通过 `SCB_PROVIDER_SECRET_DIR` 指向上述目录。模板仅给API挂载只读根密钥并提供COS出站网络，不发布API/数据库端口。无需在服务器先填桶、地域或云Secret。
4. 配置根密钥的变量为 `SCB_STORAGE_CONFIG_KEY_FILE`；直接变量 `SCB_STORAGE_CONFIG_KEY` 仅兼容已有私有环境配置，二者不能同时设置。所有API实例须使用同一根密钥；本功能不提供根密钥轮换、遗失找回或网页登录修改根密钥。

正式已有密文后丢失/更换根密钥会使COS凭据不可用，不能通过回退数据库掩盖。应独立安全保存根密钥的恢复副本，与数据库/COS文件备份分离管理。恢复隔离环境不能挂载正式密钥或正式COS外联。

## 平台管理员操作

1. 填完整存储桶名（含APPID后缀）、匹配地域；高级前缀默认 `scb-media/v1`。
2. 首次填写专用子账号的 SecretId/SecretKey，保存草稿。密钥保存后不回显；后续留空保留已保存凭据，更换必须完整成对填写。前端不持久化密钥。
3. 明确确认检测会访问云端并可能产生少量请求费用后，执行连接检测。检测验证桶的版本状态、极小检测文件的写入、回读摘要和删除；每个SDK请求有5秒上限，不代表整轮检测5秒结束。检测全局间隔至少30秒，成功结果有效10分钟。
4. 在腾讯云控制台确认专用桶私有读写且禁止公有访问，勾选页面确认。当前最低云权限不读取桶策略，连接成功不表示自动核验了全部匿名访问策略。
5. 确认目标桶并启用。前端随后重新读取服务端状态；只有实际媒体resolver确认该版本可用才显示已启用。保存成功、HTTP已受理或计时器不能代替实际生效确认。

后台有效配置优先于旧环境变量。只有确证不存在后台active配置时才沿用旧env方式；数据库、密文或配置异常会拒绝云读写，不悄悄退回数据库。历史数据库文件继续原读取路径，不因云凭据故障而必须解密云配置。

## 失败与恢复

- 请求结果未知时页面锁住后续写入，查询原commandId；404只是尚未查到回执，不是“未执行”的证明，不自动重发密钥或换新编号。
- 服务确认原检测执行者已退出后，可把中断回执收口为失败；仍保留检测对象登记和未知PUT保护。
- 对象先登记再PUT。未知PUT或进程退出留下的对象至少保留24小时后清理，避免迟到上传在一次DELETE后重新出现。已确认完成的PUT可立即回读和删除。重新检测先处理旧登记，不触碰业务文件。
- 有业务云文件或未清理检测对象时，桶、地域、前缀锁定；不提供直接切回数据库。旧active仍工作期间保存了不同目标草稿、随后旧地址产生首个文件时，使用页面「恢复为当前实际存储位置」，只回填草稿，须核对凭据并再次保存/检测。
- 只在原存储位置轮换云凭据。旧active在新草稿检测和启用之前继续使用；真实迁移桶/前缀需单独制定文件迁移与回滚计划。
- 恢复隔离标记或数据库状态不可验证时，检测、启用及运行时云访问均禁用；不会先加载凭据再拒绝。

限额仍为单文件8MiB、机构共享128MiB；本功能不增加云点播、大视频直传、CDN、自动迁移或STS自动续期。真实COS专用私有测试桶/受限凭据联调和微信真机验收需另行进行。
