# 腾讯云 COS 媒体存储（COS01）

本功能将现有报名文件、比赛图片及小视频的**新文件内容**保存至腾讯云 COS，旧 PostgreSQL 文件继续读取。既有上传、幂等回执、分片续传、公开发布、撤销和下载 API 保持兼容；前端无需填写云密钥。COS 长期凭据只在服务端使用，所有下载仍先经过原身份/机构/发布权限，不下发绕过撤销的云直链。

## 本轮边界

- 默认 `DATABASE`，不会因安装 SDK 自动访问云端。显式选择 COS 后配置错误或云故障会失败，不悄悄写回数据库。
- 本轮保留单文件 8MiB、机构共享 128MiB 的现有限额，以及 512KiB 分片；分片暂存在数据库，完成校验后入 COS 并释放。**不属于大视频直传或云点播**。直播录制/转码数据卷、已加密的本人资料版本、治理附件仍按各自存储方案处理。
- COS 中的完整文件按服务端限制读入后校验 SHA256/长度，再返回原 API 的 Range 响应。适合现有小文件，不宣称视频 CDN、流式转码或长视频承载能力。
- 新增 `049_cos_media_storage.sql`，001—048 不变。部署前必须按既有隔离升级/备份审查流程验证并执行新迁移；本轮没有执行生产迁移。

## 资源和权限

使用已有、专用于本环境的**私有读写存储桶**；开启禁止公有访问，确认桶策略没有匿名 GetObject 授权。区域须与桶一致，例如广东部署可选择已有的广州桶。不得使用公共桶、网站托管桶、主账号全权限密钥，或把正式桶/凭据用于恢复演练。

本实现要求该专用桶**从未启用版本控制**。Enabled 和 Suspended 均不支持：普通删除不会清除历史版本，且禁止覆盖语义不同。adapter 在写入/清理前检查版本控制状态，未获检查权限也会拒绝操作。若业务必须保留版本，应先实现并验证 VersionId 级生命周期，不要绕开此门禁。

子账号策略限定到指定桶与 `${SCB_COS_PREFIX}/*` 对象，仅授予本功能需要的 `cos:PutObject`、`cos:GetObject`、`cos:DeleteObject`，以及桶级 `cos:GetBucketVersioning`。不要授予列桶、删除桶或修改策略/ACL的管理权限。PUT 明确设置对象 private ACL、MD5 和禁止覆盖；对象路径由服务端随机生成，客户端不能指定桶/Key/外链。COS 管理员仍须保持桶级禁止公有访问设置。

## 配置

| 变量 | 默认值/要求 |
| --- | --- |
| `SCB_MEDIA_STORAGE` | `DATABASE`；启用时设置为 `COS`，大小写严格 |
| `SCB_COS_BUCKET` | 含 APPID 后缀的完整已有桶名 |
| `SCB_COS_REGION` | 桶的区域，例如 `ap-guangzhou` |
| `SCB_COS_PREFIX` | 默认 `scb-media/v1`；仅规范小写字母、数字、连字符路径段，不能含前导/尾随斜线或 `..` |
| `SCB_COS_SECRET_ID` / `_FILE` | 二选一；推荐挂载私有文件 |
| `SCB_COS_SECRET_KEY` / `_FILE` | 二选一；推荐挂载私有文件 |
| `SCB_COS_SESSION_TOKEN` / `_FILE` | 使用现有临时凭据时提供，不能只提供Token；本实现不自动申请或刷新STS，需外部轮换 |
| `SCB_BACKGROUND_WORKERS_ENABLED` | 已有总开关；启用后台工作时每60秒进行一批有界COS清理 |

已关联文件绑定原桶/区域/前缀。不能直接更换这些值来搬迁文件；配置不匹配会拒绝读写，不会擅自访问其他桶。切回 DATABASE 会关闭COS适配器，已有COS文件将返回503，数据库旧文件仍可读取。因此正式有COS文件后不要直接切回或回退旧程序。具体回滚方案必须先导出、校验并恢复文件内容。

## Docker 部署模板（待运维授权后执行）

可选模板：`ops/templates/compose.cos.yaml`。在现有私有 provider 目录准备 `cos_secret_id`、`cos_secret_key`，使用项目规定的容器 UID 10001、0400 权限；不要将密钥写到 env 样例、镜像、日志、命令参数或 Git。将桶名、区域、前缀作为非敏感设置加入已有私有环境文件。临时凭据还需在私有 override 中挂载 token 并设置其 `_FILE`。

现有生产 API 只有内部网络，默认无法访问云端；该可选模板追加 provider_egress 允许出站 HTTPS，不发布 API 或数据库端口，也不自动启用其它外部服务。将它与现有生产 Compose 一起使用，沿用已授权的构建、迁移、启动步骤；不要单独运行此模板或跳过新迁移。CORS、微信 uploadFile/downloadFile COS 域名无需额外开放，因为本轮请求仍通过原 API。

## 一致性、清理和恢复

1. 原业务事务完成权限、格式、摘要和配额检查，独立小连接池先持久化 `media_cos_objects` 登记，随后业务事务锁定登记并执行上传；写入新 `media_files` 时 `payload=NULL`、`cos_object_id=id`。
2. 上传结果未知、事务回滚、进程退出留下的对象保留登记。无文件关联且超过24小时宽限期后才会回收；上传持登记锁，清理使用 `SKIP LOCKED`，不会抢删进行中的文件。
   每机构未关联待清理登记上限32条、全部历史登记上限8192条；超限在新登记和云上传前拒绝。清理可释放待处理名额，历史总上限则需运维评估归档方案，不能通过直接删除登记破坏引用。
3. 文件撤销立即关闭原API访问。明确清除后释放业务额度，云对象进入后台删除；失败保留待清理状态，下一批重试。不能将 API 的 PURGED 回执当成COS物理删除成功。运维应观察通用失败日志与未清理登记数量，不打印对象路径或私密内容。
4. 后台关闭时，可在已有API容器以运行时身份执行 `node apps/api/dist/cos-cleanup-cli.js`，一次最多20个对象，输出仅含删除/失败数量。无需迁移、管理员凭据或新增服务。失败会非零退出。
5. 完整备份必须同时覆盖数据库与COS对象；数据库dump只包含对象引用，不含云文件。制定独立异地副本、校验和恢复流程，**不要对正式对象前缀配置统一TTL过期规则**，否则会删除有效文件。可单独设置未完成分片上传清理，但不得将其等同本应用登记清理。
6. 存在 `RESTORE_QUARANTINE` 标记或数据库状态无法验证时，应用不初始化COS adapter，手动清理也拒绝执行。恢复环境不能挂载正式COS凭据/出站网络。隔离恢复如需校验COS内容，先复制到独立测试桶并经专项授权处理引用。

## 上线前验证

先在独立测试桶与隔离数据库中验证：新文件 DB 无payload、旧文件可读、幂等/分片、跨机构拒绝、草稿不公开、发布及撤销、Range、摘要损坏拒绝、PUT失败登记可清理、删除失败可重试、最小权限和恢复隔离；再做微信真机和正式环境检查。没有已有桶和凭据时，源码/替身测试通过不能写成真实COS已接通。
