# 首次部署与账号密码

本说明对应首次初始化及登录后修改密码源码，部署与真实环境验收记录以当前任务交接为准；文中的操作步骤不是生产执行证据。

## 全新实例：由用户设置首位owner密码

1. 按[自托管安装说明](../../ops/templates/README.md)准备HTTPS与分离数据库身份。确认是尚未初始化的新实例，在私有部署配置设置`FIRST_RUN_SETUP_ENABLED=true`并启动API/Web。
2. 部署者在私密交互终端运行`initialization-link`一次性db-tools作业。先使用宿主入口`node ops/setup/initialization-link.mjs /srv/scb/production.env`，它在启动容器前检查宿主stdin/stdout均为TTY且不在CI，输出只继承当前终端。该作业使用维护角色，要求canonical HTTPS `APP_ORIGIN`，拒绝CI及非交互输出。不要使用`-T`、重定向、`tee`或终端录制；容器日志驱动为`none`。
3. 用户在15分钟内通过HTTPS打开私密链接，填写机构名称、管理员邮箱、显示名称、密码及确认密码。密码沿用12–128字符规则，由用户自行输入或使用密码管理器；部署人员和Agent不需要获知密码。
4. 成功后关闭初始化入口，使用刚设置的邮箱和密码正常登录。部署者将配置改回`FIRST_RUN_SETUP_ENABLED=false`并重建API容器。

令牌为至少256 bit的随机值，仅通过URL fragment交付，页面读取后立即清除地址栏、仅保留当前页面内存，通过JSON请求体提交。不写入query、Storage、应用日志、审计、遥测或错误；初始化页面使用`no-store`、`no-referrer`及同源资源限制。刷新清除令牌后需重新打开原链接。丢失或过期只能由部署者离线重新签发，新令牌使旧令牌失效；不存在公开签发或补发接口。

服务端只保存令牌摘要、到期和使用状态，到期时间不因重启续期。必须同时满足显式开启、全新实例及有效令牌才能完成网页初始化。账号、机构、`ORG_OWNER`成员关系、审计、令牌消费及完成标记在同一事务提交；任一步失败整体回滚。网页、离线签发及兼容`bootstrap-owner`共享锁和完成状态，不能并发创建两位首owner。

完成状态持久保存，升级中的真实用户或机构也使实例永久关闭初始化；只识别代码定义的不可登录系统主体，普通禁用账号和开发示例owner仍算既有实例。删除令牌、重新开启配置、重启或部署不会重开入口。公开注册不能在初始化前抢占账号/OWNER。首owner为机构负责人，不取得平台运营权限；填写邮箱不代表邮箱已验证。无需新增邮件、短信或微信服务。

## 已有账号：登录后修改密码

Web管理端点击页头“个人 ID / 邀请”，进入“账号安全 → 修改密码”，填写当前密码、新密码及确认新密码。可使用密码管理器，支持显示/隐藏密码；新密码必须符合既有规则且与旧密码不同。提交期间按钮不可重复触发。

后端从当前有效会话确定唯一目标，复核账号ACTIVE状态、当前密码及同源Origin规则，并执行限流。请求不接收其他用户ID；邮箱、`login_name`、User ID、机构关系及角色保持不变，`login_name`为空的账号同样可用。

密码更新、`credential_reset_at`、全部旧会话撤销、未消费找回密码令牌失效及审计原子提交。旧密码错误、表单错误、会话失效、非法Origin或事务失败不会修改密码和会话。成功后当前会话也失效，前端清理当前登录状态并提示重新登录。并发登录、找回密码及离线维护遵守共享锁协议，不能在密码变更后留下用旧凭据新建的有效会话。

已有找回密码功能保留；已配置邮箱服务的实例可继续使用，修改密码本身不依赖邮件。用户已登录时优先自行修改；需分配用户名或无法登录时，再按[离线账号维护](../ACCOUNT_MAINTENANCE.md)处理。本文不授权读取、展示或删除生产环境已有密码文件。
