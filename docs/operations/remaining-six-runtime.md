# 六项扩展运行配置与验收边界

此文档说明代码接线，不是生产启用记录。新功能在完成隔离 CI、独立审查和业务验收前保持关闭；恢复隔离模式强制关闭新写入及外部派发，保留历史核对事实。

| 配置                                     | 默认         | 作用                                                                       |
| ---------------------------------------- | ------------ | -------------------------------------------------------------------------- |
| `SCB_R6_MATCHING_ENABLED`                | `false`      | 开放全国撮合需求、双方意向与原预约转换                                     |
| `SCB_R6_TRAINING_ENABLED`                | `false`      | 开放成人培训服务；不开放青少年招生                                         |
| `SCB_R6_DISPATCH_ENABLED`                | `false`      | 开放跨城邀约、已核验差旅报价和原预约转换                                   |
| `SCB_R6_DISPATCH_AUTO_DISPATCH`          | `false`      | 启用派单后台推进，必须同时启用派单域                                       |
| `SCB_LOCAL_SEARCH_CURSOR_KEY` 或 `_FILE` | 进程临时密钥 | 地图分页签名，生产多实例需同一专用32字节密钥的标准Base64；不能复用支付密钥 |

开关只接受 `true` / `false`，配置错误直接阻止启动。密钥不得出现在日志或版本库；不提供固定示例密钥。未配置地图稳定密钥时重启/跨实例旧游标可能失效，客户端需重新搜索。地图区域查询延续同城既有权限/发布规则；恢复隔离禁用查询写入。

## 真实来源与资金

付费培训、球员/工作人员撮合、跨城预约必须先配置既有统一交易商户和当前有效收费条款，取得用户同意并在同一数据库事务建立真实来源及 `trade_orders`。缺配置整笔回滚，不用免费单或模拟成功兜底。培训退款按逐课分配审批，再走统一退款独立审核及原编号查询；UNKNOWN资金结果保留占用和核对义务。

广告商业服务可通过应用装配 `SponsorCommerceOptions`，或现有 `SCB_TRADE_MERCHANTS_JSON` 每个商户的严格 `sponsor` 配置接线。`SCB_R6_SPONSOR_ENABLED` 默认 `false`；为 `true` 时必须先启用统一交易且至少存在一个当前商户的广告能力映射，否则启动失败。读取配置及构造客户端不外发请求。新单关闭不免除已存在分账回退、退款解冻及原编号查询义务。退款必须确认回退和原分账解冻后进入统一退款。平台垫付只有同时配置商户自身资金退款能力、可信 `reserveAdvanceCoverage` 原子资金保留接口、与本订单/退款完全一致的不可变资金凭证以及独立双人审批后才可用；默认阻止，审核本身不代表资金到位。

保险已实现版本化供应商准入、报价准入固定、投保前复核及未知结果案件留存。真实保险供应商协议、签名证书、产品映射与正式凭证尚未提供，不能宣称已经接通供应商，不允许用自造协议或测试驱动替代。

## 验收及恢复

新增043—048迁移必须完整通过真实 PostgreSQL；既有001—042保持冻结。需覆盖双方权限、报价版本、名额/档期并发、晚到支付、UNKNOWN退款、广告回退和解冻、跨域资源竞争及44张新表持久化。运行权限由 `runtime-privileges.json` 精确列级授权。

`check-database-restart.mjs` 串联既有恢复与R6恢复清单，捕获/核验不可变事实并执行恢复隔离；离线清单通过不能代替数据库重启、真实归档恢复和旧包升级验收。主干合并与功能开放是不同动作，本任务未进行生产部署或生产迁移。

## 广告配置结构

现有统一交易商户每行可选 `sponsor` 对象，仅接受 `maximumSplitBps`（0—10000整数）、`financeActorIds`（2—100个不同UUID）、`receivers`（最多100个受益机构UUID映射）和可选 `encryptionSerial`。每个receiver仅接受 `merchantId`、`displayName`、`authorizationVersion`、`expiresAt` 和 `returnsEnabled`；不接受自己机构/自身商户/重复商户，不以配置替代数据库内当前财务及机构权限。单合同实际外部收款人仍最多10个；实际整数分金额还须满足渠道上限。

客户端复用同一商户编号、AppID、私钥secret引用、已固定平台公钥和原退款配置，不新增秘密格式。多个平台公钥时必须显式指定现有 `encryptionSerial`；单key可自动选择。历史商户使用既有 `historical` 段及相同 `orgId:key` 映射，停新单后仍保留查询/回退所需路由；财务权限只读取当前配置，不恢复已撤销的历史授权。配置拒绝垫付或自由余额字段，垫付仍需单独可信同事务资金保留实现。

Compose透传五个R6普通布尔开关且默认关闭。交易secret文件及地图游标secret仍按既有审核的私有override挂载流程接入，不将凭证放入镜像、提交或默认公开环境。这里未生成或配置真实凭证。
