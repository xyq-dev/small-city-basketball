# 产品需求与业务规则

更新：2026-10-22｜性质：开发设计基线；P01、P02、P03-A、P04-A已合并main（DONE / MAIN）；真实Web报名冻结、共享场地、单循环手工排时与一次发布已验收，完整办赛链路尚未实现。实际完成情况以 [CURRENT_STATUS.md](CURRENT_STATUS.md) 为准。

## 1. 定位与首要目标

「小城市篮球」面向赛事主办方、篮球协会、赛事公司和场馆，提供可重复使用的商业办赛工具。青锋杯是试点，赛事名称、队数、总场次、赛制和费用均不能作为全平台默认业务规则写死。

核心闭环：机构创建赛事 → 球队报名 → 名单审核 → 抽签排赛 → 现场记分 → 确认赛果 → 发布成绩及赛后交付。机构后台、身份及基础后端、P03-A Web报名审核与冻结、P04-A单循环排赛及正式发布已整合；记分、赛果与交付通过后续任务逐步完成。

商业首选是向主办方按届收费，球员、领队和观众基础使用免费。初期由平台人工开通套餐和额度；年费、直播与视频用量收费后置。当前没有确定价格，没有支付、退款、保险销售或自动计费能力。

## 2. 角色与权限边界

| 角色 | 允许的业务范围 | 不自动获得的权限 |
|---|---|---|
| 平台运营员 | 经授权开通机构、套餐和处理平台工单 | 默认读取所有机构的私人球员资料 |
| 机构管理员 | 管理本机构赛事、工作人员、品牌及套餐使用 | 访问其他机构业务数据 |
| 赛事管理员 | 管理被分配赛事的报名、赛程、赛果及交付 | 修改机构套餐或其他赛事 |
| 领队 | 管理获授权球队、提交名单、补充资料 | 审核自身报名、修改正式赛果 |
| 球员 | 填写本人资料、接受邀请、查看本人报名 | 读取全队身份证与保单 |
| 记录员／统计员 | 在授权比赛及采集模式内记录、更正事件 | 批量修改报名资料或其他比赛 |
| 直播员 | 绑定授权比赛、使用展示数据和直播包装 | 写入官方比分、读取参赛敏感资料 |
| 观众 | 查看已发布赛事、赛程、比分和允许公开的数据 | 读取未发布内容、联系方式及保单 |

同一用户可兼任多个角色，但每次操作必须带明确的机构、赛事及资源上下文。前端隐藏按钮不替代服务端授权。首版 Mock 的角色展示只是交互演示。

外部参赛者不应为报名而获得机构工作人员权限。P03-A已实现独立个人账号、绑定明确受邀User ID的领队邀请及TeamAccessGrant，接受邀请不授机构后台权限，不依靠未经验证的邮箱认领。本人参赛资料绑定和球员自助资料属于后续范围；领队填写、本人资料与工作人员审核必须保持不同授权。

## 4. 核心业务规则

### 4.1 机构与赛事

- 赛事属于一个机构；同名赛事在不同届次、机构中不能被误认为同一资源。赛事标题允许重复，资源 ID 不允许混淆。
- 草稿仅获授权工作人员可见；对外展示需经过显式发布。状态变化遵循后端契约，不能只改前端文案。
- 赛制、统计模式、报名人数上下限、资格条件、积分和同分排序规则应在对应流程开始前明确；锁定后修改要保留版本并检查影响。
- 不因青锋杯示例而固定 8 队、16 场、19:30 或任何保证金金额。暂不实现的赛制不在可用选项中伪装为已支持。
- 赛事主流程统一为 `DRAFT → REGISTRATION_OPEN → REGISTRATION_CLOSED → SCHEDULED → RUNNING → COMPLETED → ARCHIVED`，另有 `CANCELLED`。比赛主流程统一为 `SCHEDULED → READY → LIVE → PENDING_CONFIRMATION → FINAL`，另有 `POSTPONED`、`CANCELLED`。这不是任意改状态接口；前置条件、取消及恢复路径以数据/API 契约为准。

### 4.2 球队、名单与审核

P03-A已交付：长期球队及成员、明确账号的领队邀请/撤权、独立报名名单revision、提交/退回补交/重提/独立审核、关闭报名和freeze。审核者不能是本队当前领队或最近提交人，机构OWNER不例外；获批名单修改先退回，不能直接覆盖旧revision。关闭后仅允许已有CHANGES_REQUESTED补交。冻结只取获批版本，显式显示被排除的草稿/拒绝/撤回数量，之后禁止报名及审核写入。具体边界见[API契约](API_CONTRACTS.md)及[P03-A卡](tasks/P03-A.md)。

以下同时保留后续完整P03的目标要求，不能把尚未接入的身份、保险文件或球员自填功能视为当前能力。

- 长期球队成员和本届报名名单分别保存。球队成员离开、改名或改号码，不可静默重写历史名单及统计。
- 球员可自行填写资料，领队汇总提交。是否允许领队代填、是否需要身份证由赛事资格规则决定；只收集审核所需字段。
- 报名支持草稿、提交、退回补充、重新提交、通过及撤回等业务动作；具体枚举与并发约束由数据/API 契约定义。退回必须给原因，通过后改名单需重新审核受影响内容。
- 每届赛事按其规则检查人数、球衣号码及重复参赛；不通过全局搜索暴露其他机构的私人名单。提交与审核必须分权。
- 保险凭证规划支持外购上传，记录审核结果和原因；当前尚未实现文件服务。上传文件不等于已投保、保险有效或保险公司承保；审核不能伪装成自动保险验证。保险购买另行选定服务方后设计。
- 资料可见范围按用途和角色控制，公开阵容只包含允许展示的姓名、号码等字段；身份证、联系方式和保单不可进入排行榜或 OBS 数据。

### 4.3 抽签与赛程

P04-A已交付以下范围，完整规则和验收见[任务卡](tasks/P04-A.md)及[CI 39737812114](https://github.com/xyq-dev/small-city-basketball/actions/runs/39737812114)：

- 唯一参赛来源为本届已保存的不可变冻结名单，仅支持2–32队、单循环一回合。每对球队恰好比赛一次，奇数队轮空不创建假比赛；不重新读取长期成员作为参赛名单。服务器持久化随机种子与对阵来源，同一输入及种子可复现。
- 场地为机构共享资源；改名不覆盖发布时的场地名称，存在未来正式占用时不能停用。当前机构内不同赛事使用同一场地或同一球队的重叠时间均为硬冲突；跨机构物理场馆共享尚未纳入检查。
- 占用分钟、同届最少休息分钟、最小开赛日期差及场地可用窗口必须显式配置，允许明确填写0休息或0日期差。当前时间输入按中国标准时间处理；比赛需完整落在有效窗口和赛事日期内，不自动放宽限制或自动搜索开球时间。
- 工作稿按轮手工分配场地与时间，全量保存检查赛事和工作稿两个版本。未保存的本地修改不算成功；版本冲突保留输入并提示重读。发布前可填写原因重新生成新稿，旧稿及原因只读保留，不能覆盖历史。
- 发布前检查可定位未分配、越界、停用场地、场地／球队重叠、休息和日期间隔问题；检查通过不是场地预约或发布凭证。正式发布事务再次核验当前权限、版本与最新占用，原子保存正式计划及占用、审计，并把赛事从REGISTRATION_CLOSED转为SCHEDULED。
- 仅机构负责人、管理员或该场实际EVENT_MANAGER可生成、分配、检查及发布，其他授权工作人员只读；球队grant不授后台排赛权限。一次发布后计划只读，不提供重抽、编辑、重复发布或改期入口。正式比赛初始SCHEDULED不表示已开赛、已记分或已公开观赛。

种子队约束、分组／淘汰、双循环、自动优化、首末场均衡和发布后受控改期仍属后续P04任务。退赛、弃权、积分、同分排序与晋级规则须在依赖流程实施前明确，不由首卡排赛默认补齐。

### 4.4 记分、统计与结果

本节为P05目标，当前尚未实现记分、正式赛果或榜单。

- 一场比赛同一时刻只有一个有效主记分写入端。设备交接、断网、重连和过期会话必须按契约处理，不能用浏览器内计分演示冒充生产可靠性。
- 操作产生可追溯比赛事件，幂等重放不重复计分；撤销、更正保留原记录并一致更新比分、球员统计和下游展示。
- 基础模式只采集比分、节次、犯规和暂停等已支持字段；未采集的篮板、助攻显示“未统计”。专业模式按现场人手启用。
- 比赛计时与录像时间分别记录。比赛暂停不能让录像时间停止；集锦依赖事件与媒体时间映射，不能假设自动识别所有球员事件。
- 终场记录和正式赛果确认分开。确认后更正需原因、权限和影响检查；积分、晋级、榜单按确认后的有效结果计算。

### 4.5 OBS 与商业交付

本节为后续目标，当前尚未接入OBS、云直播、录像或商业交付服务。

- OBS 负责采集、导播和推流，平台提供只读比分包装与事件数据。断开 OBS 不影响记分，包装失联时提示数据陈旧。
- 包装地址限定比赛及展示范围，可撤销和轮换；不携带管理员权限或参赛敏感资料。推流密钥仅授权人员可操作，不出现在公开页面和日志。
- 录像、直播、集锦的可用性与套餐分开显示；未接入时不能展示“直播中”或虚构已交付内容。
- 套餐授权和实际用量可追溯；视频成本、人工支持和软件费分别核算。真实浏览及点击报告上线前，不提供臆造的赞助效果数字。
