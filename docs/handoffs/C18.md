## 实现

### 数据（Migration 018）

- 表 `event_directory_listings`：
  - 字段：列入人、时间、列入时赛事版本、城市、原因，撤出时间、来源（`UNLIST` / `PUBLICATION_REVOKED` / `ORGANIZATION_DISABLED`）、原因与操作者；
  - 复合外键：`(org_id, event_id)` → events；`(org_id, event_id, publication_id)` → public_event_publications；
  - 部分唯一索引 `event_directory_one_active`：每个机构/赛事至多一条 ACTIVE；
  - CHECK：城市规范形式与字符集、原因 4–500 字、撤出字段整体一致；`ORGANIZATION_DISABLED` 时操作者必须为空，其余来源必须非空。
- 守卫触发器 `c18_directory_listing_guard`：
  - 禁止 DELETE 与 TRUNCATE；
  - INSERT 必须为 ACTIVE，机构 ACTIVE（`FOR SHARE`），公开授权未撤销、用途与赛事状态一致；
  - UPDATE 只允许 ACTIVE→REVOKED，身份字段不可改；不能复活，重新列入插入新行。
- 窄触发器（同一事务）：
  - `public_event_publications.revoked_at` 由空变非空：撤出该授权下的 ACTIVE 条目，来源 `PUBLICATION_REVOKED`，操作者沿用授权撤销者；
  - `organizations.status` ACTIVE→DISABLED：撤出该机构全部 ACTIVE 条目，来源 `ORGANIZATION_DISABLED`，操作者为空，原因为固定系统说明；
  - 自动撤出不再推进赛事版本；机构重新启用或重新开启公开观赛均不自动列入。
- 迁移本身不含顶层 DML，不列入任何赛事。

### 与实际代码的关键冲突与处理

- **触发器以调用者权限执行**：readiness 禁止 SECURITY DEFINER 函数，因此由运行时角色执行撤出更新。运行时权限清单为目录表只给 `SELECT, INSERT`，以及限定五列的 `UPDATE`（`status, revoked_at, revoked_by, revoke_source, revoke_reason`），**没有 DELETE**。身份字段由守卫触发器锁定。
- **隔离批次的操作者**：隔离批次以系统用户撤销公开授权，目录条目的撤出操作者因此是该系统用户（非空），来源 `PUBLICATION_REVOKED`。P07 隔离测试已断言。
- **自动撤出不写 `audit_logs`**：现有 `audit_logs` 要求操作者，机构停用的自动撤出没有用户，因此不伪造用户、不放宽审计表；撤出事实与系统原因记录在目录行本身。授权撤销本身已有原命令的审计。
- **事务内的版本**：LIST/UNLIST 推进赛事版本，因此同一页面上的后续操作需要重新读取（真实 API 流程中，org-event 完赛前先刷新）。这是 CAS 的预期行为，不是回退。

### API

- 私有：
  - `GET /v1/orgs/:orgId/events/:eventId/directory`：返回状态、当前授权、当前与最近一条目录条目、可列入分组和能力；
  - `POST …/directory-commands`：`{type LIST|UNLIST, expectedEventVersion, displayCity?, reason}`。
- 加锁顺序：身份 → 机构 → 赛事（`FOR UPDATE`）→ 公开授权（`FOR SHARE`）→ 目录条目（`FOR UPDATE`）。
- 错误码：
  - 非工作人员 404，无权 403；
  - 409：`VERSION_CONFLICT`、`DIRECTORY_ALREADY_LISTED`、`DIRECTORY_NOT_LISTED`、`PUBLIC_VIEWING_NOT_ENABLED`、`INVALID_EVENT_STATE`；
  - 422：输入校验失败。
- 匿名 `GET /v1/public/directory`：
  - 参数：status 默认 LIVE；limit 默认 20、最大 50；city 与 cursor 可选；未知参数、重复参数返回 400 `INVALID_QUERY`；
  - 单条 SQL 同时联结机构（ACTIVE）、赛事、公开授权（未撤销）与分组条件；
  - 键集排序：LIVE/UPCOMING 按 startDate 升序，HISTORY 按 endDate 降序，同序按 publicEventId 升序（`COLLATE "C"`）；取 limit+1；
  - 游标：base64url `{v,s,c,d,k}`，不做 HMAC；解码后严格校验并要求规范重编码一致，与当前分组、城市不一致即 400 `INVALID_CURSOR`；游标未签名，合法重编码的分页位置可能被接受，它不是授权凭据，每页 SQL 都重新检查有效公开条件（C19 订正：不能表述为“篡改必定返回 400”）；
  - 返回白名单 8 个字段；`Cache-Control: no-store`；不读取、不设置 Cookie；
  - 限流：可信客户端 IP 每分钟 60 次，复用 `auth_rate_limits`，键为 IP 哈希。

### 小程序

- `utils/directory.js`：
  - 只经 `requestPublic`：无 Cookie、不读 Set-Cookie，401 也不会退出登录；
  - 严格白名单解析；城市规范化与服务端一致。
- 路径白名单：
  - 匿名目录只放行精确参数；
  - 私有的 `directory`（GET）与 `directory-commands`（POST）不带查询参数。
- watch“公开赛事”：
  - 进行中 / 即将开始 / 历史赛事，默认进行中；
  - 城市筛选，包括加载、空、错误重试与加载更多各状态；
  - 每次重置（筛选、刷新、重新进入）开新代次，旧代次迟到响应丢弃；
  - 重置先清空条目，失败时不展示旧条目；
  - 加载更多失败保留已读条目，可按原游标重试。
- event-setup“公开赛事目录”卡：
  - 显示状态、分组、城市和自动撤出原因；
  - 列入 / 撤出均经 `ui.confirmOp`，弹窗前固定赛事版本、公开授权与条目，回答后核对，发送前再核对 `op.valid()` 与写入令牌；
  - 409 时重新读取并保留提示；结果未知时提示刷新核对，不直接重复提交；
  - 会话重置时清除缓存的目录状态。
