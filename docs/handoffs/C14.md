## 已实际可用（原生页面＋真实API联调）

- **赛事主线**：创建赛事草稿 → 报名规则 → 开放报名 → 领队接受邀请、建报名、保存名单、提交 → 独立审核通过 → 截止、冻结 → 添加场地、生成单循环对阵、排入时间、服务端校验、发布 → 记分/积分规则、锁定积分规则 → 分配记分员 → 准备比赛（逐人记分）→ 记分台（租约续约、得分/犯规、计时、撤销、结束）→ 他人独立确认 → 积分榜与球员数据 → 开启公开观赛 → 观众分享直达与最近观看 → 完赛（公开身份撤销、观众页清屏并移除）→ 退出后私有页面清空。
- **预约扩展**：球员提交资料 → 平台独立审核 → 选人/同价比较 → 创建预约（响应丢失按原命令恢复，只生成一单）→ 球员接单 → 到场 → 领队确认完成（按真实结束时间）→ 支付保持未开放 → 切换账号清空订单页。
- **新页面**：org-match（单场）、scorer（记分台）、scoring-tasks（记分任务）、entry-review（报名审核）、event-setup（赛事设置）、schedule（排赛）。“我的”分组入口含切换账号/退出；视频页直达最近观看赛事的已发布媒体。

## 实际修复的缺陷

- **booking-detail 无法读取订单**：页面定义了 `route()` 方法，而运行时每个 Page 实例都带 `route` 字符串属性，`this.route()` 在读取订单前抛错。VM 测试环境按运行时设置该属性后暴露（C12 截图副本禁用业务逻辑，无法发现）。改名 `returnPath()`，结构测试禁止页面方法与内置实例属性同名（修复前该测试失败）。未在微信开发工具/真机复现，判断依据为运行时属性规则与 VM 复现。
- 共享样式错放：org-event 页面样式中的比赛行/表格类被其他页面复用但不生效，移入 app.wxss。
- 320宽：我的预约“我收到的”被裁切（单类选择器输给内置184px按钮宽）；积分表胜负列折行；时长<1分钟显示为“0分钟”。
