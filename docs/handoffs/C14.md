## 已实际可用（原生页面＋真实API联调）

- **赛事主线**：创建赛事草稿 → 报名规则 → 开放报名 → 领队接受邀请、建报名、保存名单、提交 → 独立审核通过 → 截止、冻结 → 添加场地、生成单循环对阵、排入时间、服务端校验、发布 → 记分/积分规则、锁定积分规则 → 分配记分员 → 准备比赛（逐人记分）→ 记分台（租约续约、得分/犯规、计时、撤销、结束）→ 他人独立确认 → 积分榜与球员数据 → 开启公开观赛 → 观众分享直达与最近观看 → 完赛（公开身份撤销、观众页清屏并移除）→ 退出后私有页面清空。
- **预约扩展**：球员提交资料 → 平台独立审核 → 选人/同价比较 → 创建预约（响应丢失按原命令恢复，只生成一单）→ 球员接单 → 到场 → 领队确认完成（按真实结束时间）→ 支付保持未开放 → 切换账号清空订单页。
- **新页面**：org-match（单场）、scorer（记分台）、scoring-tasks（记分任务）、entry-review（报名审核）、event-setup（赛事设置）、schedule（排赛）。“我的”分组入口含切换账号/退出；视频页直达最近观看赛事的已发布媒体。

## 实际修复的缺陷

- **booking-detail 无法读取订单**：页面定义了 `route()` 方法，而运行时每个 Page 实例都带 `route` 字符串属性，`this.route()` 在读取订单前抛错。VM 测试环境按运行时设置该属性后暴露（C12 截图副本禁用业务逻辑，无法发现）。改名 `returnPath()`，结构测试禁止页面方法与内置实例属性同名（修复前该测试失败）。未在微信开发工具/真机复现，判断依据为运行时属性规则与 VM 复现。
- 共享样式错放：org-event 页面样式中的比赛行/表格类被其他页面复用但不生效，移入 app.wxss。
- 320宽：我的预约“我收到的”被裁切（单类选择器输给内置184px按钮宽）；积分表胜负列折行；时长<1分钟显示为“0分钟”。

## PR #23 审查修复（2026-10-27）

**读写并发**。原因：读取（轮询、刷新、onShow）与写操作共用 `ui.begin` 请求令牌，后开始的读取会使进行中的写令牌失效，成功响应被丢弃、busy 永久为 true；org-match 的 `bindtap="load"` 把点击事件当成 `quiet=true`。修复：
- `utils/ui.js` 新增 `hold/held`：写操作开始时取消进行中的读取（含页面 `_load` 读代次），再持有只受会话变化或页面关闭影响的令牌；`guard` 供补充读取（成员列表、记分历史）使用独立计数，既不取消也不被读取取消。会话版本校验、onSessionReset 清空不变。
- 各页 `load` 在 busy 时不启动，写操作开始时清除被取消读取残留的 loading，写完成后照常重读一次；刷新按钮在 busy 时禁用。org-match 刷新改为 `refresh()`（完整读取）；单场命令以确认弹窗前看到的版本做 CAS，弹窗期间如有轮询更新则服务端版本冲突并重读。
- 同源页面一并修复：scorer（命令、取得控制、核对/重发、历史）、entry-review（审核、报名阶段、打开报名，弹窗后复核）、event-setup、schedule、org-event（完赛等，弹窗后复核）。commandId、租约、CAS 均未改动。

**规则无损读写**（event-setup）。同分比较按服务端顺序展示并带序号，只有组织者“启用/停用/上移”才改变顺序，仅改积分时原样回传；节时与加时改为“分钟＋秒”输入，按服务端整秒精确读回与保存（1秒–60分钟、1秒–30分钟，秒数0–59），不再四舍五入。只读状态展示完整比较顺序与加时时长。未改动后端规则。

**回归（先在旧代码上复现失败，再修复）**：`apps/wechat/test/c14-review-fixes.test.cjs` 12项——轮询先启动且会话响应延迟时分配人员、确认赛果中点刷新、刷新为完整读取、写失败（版本冲突）、丢失响应按原 commandId 核对（期间刷新）、写入中切换账号、报名审核中刷新、记分台命令中重读、赛事设置保存中刷新、非默认同分顺序仅改积分后不变（含部分与空顺序）、显式上移/停用、秒级节时原样保存与精确编辑。旧代码上除“写入中切换账号”（保护既有行为）外 11 项失败。

**真实联调更新**：赛事主线中 1 秒节时改由原生表单直接设置（不再用 HTTP 覆盖），并在真实 API 上核对保存结果；设置非默认比较顺序（胜场优先）后只改胜场积分，服务端顺序不变；确认赛果进行中点击刷新，命令完成且 busy 结束。新增夹具 `c14-event-setup-rules`（可编辑规则表单，真实数据），并用同次运行数据刷新 `c14-event-setup-draft/viewing`。

结果（本机实际执行）：`npm run test:wechat` 361项，357通过，4失败为同一组 Windows 基线；`npm run test:wechat:api` 2/2 通过（赛事约12秒、预约约3.5分钟）；三宽布局 768/768 通过；改动文件 Prettier 与 `git diff --check` 通过。
