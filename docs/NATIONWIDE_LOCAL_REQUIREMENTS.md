### 核心结论

建设一个全国统一的篮球赛事与本地服务平台。用户可在全国找赛事、看直播、查球队与球员数据，也可按当前城市找到附近赛事、球场和服务。石鼓作为首个运营样板，平台结构支持逐城扩展。

首发选择“全国可浏览，高州可办赛与提供已核验服务”。先用真实赛事沉淀球队、球员和内容，再扩大有能力履约的城市。付费球员邀约、全国自动撮合和复杂广告分成后置。

| 设计决策 | 采用方案 |
| --- | --- |
| 统一产品 | 一个小程序 一个账号体系 多机构管理 城市频道 |
| 主导航 | 首页 赛事 同城 球队 我的；数据与视频保留专门入口 |
| 地域规则 | 全国内容 当前城市 附近距离 实际服务范围分别管理 |
| 收入首选 | 面向组织者的赛事工具与机构套餐；本地服务交易分阶段开启 |
| 首发主链 | 机构审核 办赛 报名保障 排程 现场记录 赛果公示 |
| 设计原则 | 内容真实 服务可履约 数据可追溯 权限可核验 |

## 02  用户角色与权限

同一个账号可以拥有多种身份。权限绑定机构、球队、赛事或具体比赛，进入工作界面时显示当前身份与作用范围。

| 角色 | 主要任务 | 权限边界 |
| --- | --- | --- |
| 观众与球迷 | 浏览 关注 观赛 分享 举报 | 公开只读；不读取证件 保单 联系方式 |
| 球员 | 维护档案 加入球队 报名 接受邀约 | 仅管理自己的私有资料；参赛资格逐赛审核 |
| 领队与教练 | 管理名单 报名 邀约 确认履约 | 限所属球队；队员授权与资料补充需留痕 |
| 机构管理员 | 管理机构 工作人员 赛事 服务 | 限本机构；财务和敏感资料单独授权 |
| 赛事负责人 | 赛制 审核 排程 赛果 申诉 | 限指定赛事；更正必须有原因与版本记录 |
| 裁判 | 执裁 接收任务 提交意见 | 执裁权与系统赛果确认权分别配置 |
| 记分员 记录员 | 计分计时 球员事件 技术统计 | 限指派比赛；同一操作者不能确认自己记录的赛果 |
| 直播 摄影 医务 | 接单 执行任务 提交凭证 | 直播仅管理媒体；医务仅见履约所需信息 |
| 财务与客服 | 退款 对账 或处理工单 | 财务不得擅自改赛果；客服无默认证件读取权 |
| 平台人员 | 入驻审核 内容治理 平台支持 | 跨机构访问另授权 记原因与审计；不默认代操作 |

### 权限执行规则

- 隐藏按钮只改善界面；每个读写接口必须检查当前账号、资源归属与具体权限。切换账号或机构后清理私有缓存。

- 一个机构可能覆盖多个城市；赛事举办地、球队所在城市、机构驻地不能代替资源授权。

- 赛果确认、名单更正、敏感资料查看、退款审批、付款配置和只读链接撤销都单独记录操作者。

## 03  全国与同城的地域规则

定位决定内容推荐的起点，不限制用户跨城市浏览。四种地域概念分别保存、展示和校验。

| 概念 | 确定方式 | 产品行为 |
| --- | --- | --- |
| 全国范围 | 用户选择全国内容频道 | 搜索全部已公开赛事与档案；不表示全国服务均可订 |
| 当前城市 | 用户确认的频道城市 | 影响同城内容与默认筛选；与个人常驻城市独立 |
| 附近距离 | 授权设备位置或手动所选地标与场馆坐标 | 显示起点来源与直线距离；仅有城市时不显示距本人米数 |
| 服务范围 | 审核通过的城市 区县 区域或半径及版本 | 按订单实际服务地点校验覆盖 档期 库存；不根据浏览城市或本人GPS推断 |

### 首次打开与切城

首次先显示全国内容，提供可关闭的引导及三个入口：**定位当前城市／手动选择城市／先浏览全国**。不先弹系统定位授权或强制登录。用户点击定位后再说明用途并申请必要授权；定位和城市解析成功后展示候选，由用户确认使用。拒绝、超时或解析失败时可直接手动选城，不循环索权。

城市选择支持搜索、最近选择、完整行政层级与区县。再次进入恢复最近明确选择，并标注“上次选择”，不为恢复偏好自动定位。主动定位发现异地时并列显示原浏览城市和新城市，由用户决定切换或保留；分享链接直接打开对应赛事，不强迫选城或改变全局选择。

附近查找支持当前位置或手动所选场馆／地标作起点。仅有城市时不展示“距你500米”；直线距离与实际路线耗时分开。拖地图后由用户点击“搜索此区域”；跨城或扩大范围须明确选择，切城重置列表分页并丢弃旧响应，保留原订单、报名草稿和服务地点。

### 无供给与跨城行为

- 当前城市没有赛事：显示真实空态，提供邻近城市与全国推荐，并标明所属城市。

- 服务未覆盖：可查看介绍、关注开放或提交需求；隐藏购买或明确不可预约。下单后不能因切城丢失订单。

- 跨城邀约：确认比赛地点、服务时间、交通住宿及履约范围后才能确认订单。

地区使用稳定内部ID、行政层级与版本记录；高州县级市及石鼓等下级地区不能仅依赖地图返回的city字符串。场馆另存坐标系及经纬度，地图检索与距离计算统一坐标系，行政区划更新不破坏历史赛事归属。

详细规则及来源见 [定位选城、附近发现与服务可预约性要求](design/LOCATION_SERVICE_REQUIREMENTS.md)。设备位置短期按需使用，不后台追踪，不作为户籍、身份、保险或到场凭据。定位权限、地图准入与第三方能力仍须实施前核验；本次没有开通接口。

## 04  产品结构与导航

观众首先找到赛事，参赛者找到球队，本地需求进入同城。复杂办赛任务进入机构工作台，移动端提供必要协同操作。

| 底部导航 | 一级内容 | 主要后续页面 |
| --- | --- | --- |
| 首页 | 同城精选 全国热门 今日比赛 | 搜索 观赛码 赛事推荐 快捷入口 消息 |
| 赛事 | 赛事 比赛 直播 关注 | 赛程 积分 分组淘汰 球员统计 阵容 视频 |
| 同城 | 球场 球员邀约 人员服务 | 附近筛选 详情 可用时间 发布需求 服务订单 |
| 球队 | 我的球队 球队广场 | 成员 赛季 日程 报名 邀请 球队主页 |
| 我的 | 个人档案 我的报名 我的订单 | 关注 通知 客服 隐私 角色工作台 机构入驻 |

### 三个工作界面

- 微信小程序：全国发现、同城服务、观赛、球队、报名、订单与工作人员移动协作。公开浏览不要求先登录。

- 机构网页工作台：创建赛事、赛制与报名审核、抽签排程、人员分配、正式数据、媒体传播和财务。记录台适配电脑与平板。

- 平台后台：机构与城市供给、内容治理、套餐订单、交易异常、客服、审计和运行监控。

### 操作时再要求必要身份

浏览和看公开赛果无需补齐球员资料；关注、报名、邀请或下单时登录。身份核验只在必要业务节点进行。普通用户不默认看到大量工作人员按钮；有权限的用户从“我的”进入对应工作台。

原首页中的“数据”和“视频”保留为强入口；“同城”获得独立导航，形成全国内容与本地服务的清楚区分。

## 05  全国化首页设计

首页保持蓝橙品牌和赛事优先，把本地内容与全国内容做成明确的浏览范围，不把某个城市写入品牌或固定业务规则。

| 模块顺序 | 展示与操作 | 核心规则 |
| --- | --- | --- |
| 顶部 | 品牌 当前城市 搜索 消息 观赛码 | 保留城市来源；搜索赛事 球队 球员 |
| 内容范围 | 同城精选 全国热门 | 切换内容范围不修改当前城市或常驻地 |
| 主视觉 | 当期真实赛事或城市篮球主题 | 无当期活动时使用品牌主题；不伪造报名与直播 |
| 八项入口 | 观赛 报名 榜单 视频 球员 球队 球场 服务 | 按实际能力开放；不可用功能不引导付款 |
| 今日比赛 | 日期 赛程 比分 节次 时间 提醒 | 直播比分与已确认赛果区分；断网显示更新时间 |
| 精选赛事 | 同城优先或全国热门 真实状态 | 标注举办城市 报名或进行中；可关注 |
| 同城服务 | 可订场馆或已核验服务供给 | 真实覆盖 档期与数量；无供给则显示需求入口 |
| 视频与运营 | 有授权的视频集锦 少量合作位 | 广告明确标识；不遮挡核心操作 |

### 交互与示例文案

顶部示例为“高州 · 石鼓”，旁边提供城市切换；全国频道中广州赛事标注“广州”。没有定位时显示“选择城市”，仍可点“全国热门”。同城无可订服务时显示“本地服务正在开放，可提交需求”。

观众默认快捷入口以消费内容为主。“创建赛事”和“工作人员”移至角色工作台；机构用户可在首页显示一条紧凑的“继续管理赛事”入口。

### 与现有首页图的调整

保留搜索、观赛码、今日比分和视频模块；新增全国与同城范围、真实服务覆盖提示和同城导航。石鼓内容作为示例与首个城市内容，不作为全站固定数据。

## 06  赛事发现与观赛

全国赛事承接增长，公开赛事页承接分享和长期数据。内容城市、赛事阶段与比赛状态都能单独筛选。

### 发现与详情

赛事列表支持城市、日期、报名状态、赛制和关键词；比赛列表支持直播、未开始、已结束及关注。赛事详情提供简介、规则版本、场馆、报名、赛程、积分、分组与淘汰图、球队、球员榜、公告和视频。

| 观赛页面 | 首要信息 | 交互与数据规则 |
| --- | --- | --- |
| 比赛实况 | 双方 比分 节次 计时 数据新鲜度 | 关注 分享 切换统计；没有媒体时不显示视频直播按钮 |
| 技术统计 | 球队对比 球员数据 出场信息 | 未采集显示未统计；有依据的0才显示0 |
| 文字实况 | 发生时间 事件 球员 数据来源 | 同步已接收事件；标明记录中与已确认 |
| 直播与回放 | 视频来源 权限 清晰度 赛况 | 媒体需有来源授权；不可用时保留比分观赛 |
| 积分与榜单 | 确认赛果 计算规则 样本门槛 | 仅符合规则的正式数据参与榜单；更正后重算 |

### 观赛码与分享链接

观赛码支持手动输入与扫码。公开页只读授权包含资源范围、有效期和撤销状态，不能凭链接写比赛。撤销或过期后清理最近观看中的失效入口，页面不继续暴露受限数据。

### 直播与数据异常

- 直播与比分是两个可独立运行的能力；直播中断时明确提示，不能伪装播放成功。

- 数据断线保留最后一份快照，显示“更新已暂停”和更新时间；重连后按版本补齐。

- 有纠纷或更正时显示待确认、申诉中、已更正等标记，保留正式结果来源。

## 07  球队 球员与邀约

个人档案可复用，球队成员关系与某届赛事参赛资格分别管理。加入球队不等于完成参赛报名。

### 球队与球员档案

球队包含所在城市、机构或个人归属、成员与角色、赛季日程、参赛记录、队徽和对外介绍。公开页显示经授权的信息；队内名单、联系方式和报名资料按权限显示。球员可维护公开昵称、号码、位置、城市和正式比赛数据，私有证件独立保存。

同一球员可以存在不同时间、赛季或项目的球队关系；是否允许同一赛事跨队、重复报名、临时替补由该赛事规则判断，不能用全平台永久独占限制代替资格审核。

### 球员邀约流程

领队发布需求或定向邀请 → 球员表达接受意向 → 核验档期与赛事资格 → 双方确认条件 → 参加活动 → 队长确认与申诉处理。存在报酬时进入独立订单，接受邀请不等于已付费或已获参赛资格。

| 节点 | 必须明确的内容 |
| --- | --- |
| 发布需求 | 城市 场馆 时间 位置需求 赛事规则 服务条件 |
| 接受意向 | 可出席时间 现有冲突 地区或年龄条件 退出责任 |
| 正式确认 | 双方身份 参赛审核结果 报酬与交通住宿约定 |
| 履约核对 | 到场凭证 参加情况 队长确认 争议证据 |
| 公开展示 | 避免精确住址与实时位置；联系方式经双方同意后受控提供 |

### 首发范围

首发支持球队邀请、成人球员资料与非付费意向匹配，先采用审核与人工协助。付费邀约须在交易、退款、纠纷和服务资质边界验收后开放。青少年赛事与监护人确认作为后续独立能力，不直接套用成人流程。

## 08  赛事创建与赛制

2026-10-29补充：管理员可选择已确定球队录入或公开招募，两路汇入同一资格审核、名单冻结与排赛；赛程生成前的公开招募页独立发布，不直接公开私有赛事。完整8队流程、季军赛及现状差异见 [办赛与球员报名专项要求](design/EVENT_REGISTRATION_PHOTO_REQUIREMENTS.md)。

先明确赛事规则与数据结构，再创建报名、抽签和赛程。规程版本随赛事保存，重要修改影响已报名用户时触发通知与重新确认。

| 配置组 | 主要字段与规则 |
| --- | --- |
| 基本信息 | 赛事名 举办城市 场馆 主办机构 时间 联系方式 公共介绍 |
| 参赛资格 | 成人组 地区 年龄 队伍数 人数 跨队规则 名单截止 替换条件 |
| 比赛规则 | 五人制 节数 节时 暂停 犯规 加时 预计占场时长 缓冲 |
| 赛制与排名 | 小组单循环 淘汰或组合 晋级配对 积分 同分判定 |
| 人员与发布 | 负责人 裁判 记分 记录 直播等分配 发布审核 可见范围 |
| 费用与保障 | 报名费 保证金 退款规则 保险要求 签署内容 服务主体 |

### 八队十六场的规范示例

八队分为A、B两组，每组四队组内单循环：每组6场，共12场；两场半决赛、一场季军赛、一场决赛，共4场；合计16场。若八队全部单循环则为28场，不能把两种赛制使用同一场次总数。

分组与淘汰赛分别建立阶段；晋级位来源为小组名次或前序比赛胜负方。人数不满足、缺队或存在轮空时自动校验并显示明确方案，不能复制队伍填满。首发只开放经过测试的模板。

### 生命周期与变更

赛事草稿、审核、已发布、进行中、已结束、归档为主生命周期。报名开关、公开状态、名单冻结与赛程版本另行管理。开赛后更改排名规则、晋级规则或参赛名单须走受控更正，不能静默覆盖历史。

比赛取消、改期或前序赛果更正后，需要重新检查后续晋级、人员档期、保单期间与订单。下游比赛已进行时，阻止自动重排并交由有权人员处理。

## 09  报名 保险与参赛资格

**本人照片必须上传**：本次实名报名需姓名、身份证号码、球衣号码及清晰本人正面照片；照片用于私有相貌核对及经单独明确授权的宣传海报。没有照片或上传尚未确认只能保存草稿，不能提交正式报名；默认头像、队徽和他人照片不能替代。本人照片不等于身份证照片，不自动要求证件正反面或活体视频。

照片原图、人工核验与公开宣传用途分开管理。宣传授权不能默认勾选；未同意宣传不豁免照片上传，也不单独阻止参赛，可用不含个人照片的海报。照片替换需重新审核，冻结名单保留当时照片版本；海报不含身份证、联系方式或保单。详见 [照片、授权、海报与验收规则](design/EVENT_REGISTRATION_PHOTO_REQUIREMENTS.md)。

报名资料、缴费、保险、签署和参赛资格分别判断。缴费成功不能自动使一名队员获得上场资格。

### 队伍与队员流程

领队选择球队并发起报名 → 邀请队员本人确认 → 填写必要资料并上传必需的本人照片 → 阅读并签署赛事文件 → 资格预审 → 选择已有保单上传或在线投保出单 → 保障核验及必要费用检查 → 领队提交队伍名单 → 组委会最终审核 → 名单冻结。队长查看进度与补充提醒，不默认读取所有队员完整证件。

| 检查项 | 通过条件 | 异常处理 |
| --- | --- | --- |
| 身份与资格 | 符合该赛事年龄 地区 跨队与禁赛规则 | 退回补充或拒绝；说明原因 可申诉 |
| 签署 | 对应版本 已确认 本人可追溯 | 规程重大变更后按影响范围重新确认 |
| 保障 | 被保险人 期间 运动项目及要求匹配 | 待审核 不通过 已失效；改期后重核 |
| 费用 | 服务端支付确认或合规线下核验 | 支付处理中不假报成功；退款后重判条件 |
| 最终资格 | 全部必选条件成立且名单版本有效 | 冻结后替换走更正；保留旧版本与理由 |

资格预审优先于保险购买，减少资格不符后的无效支出。保险费、报名费和保证金分开记录；支付成功、保单出单、保障审核通过和最终报名通过是不同状态。已付款待出单或出单失败须有查单、补出或退款跟进；不得要求不明结果下重复付款。实际服务商与产品尚未接入时只提供外部保单审核，不伪造在线投保成功。

### 两种保障路径

已有外部保单：上传图片或PDF，填写保险机构、保单号、被保险人和期间；人工核验保障运动、所需额度与真实性，审核结果可退回补充。对未核实资料不显示已投保。

在线投保：由具备相应资格的保险机构在其合规页面承接展示、投保、收款、出单与售后，小城市篮球只在确认合作范围后提供入口和授权状态同步。未接通时仅提供外部保单审核，不自行承保、代收保费或设计保险销售方案。[5]

对外页面仅展示“保障审核已通过”等最小必要状态。完整证件、保单与签名资料隔离存储，按用途授权，访问和导出均可追溯；不使用绝对免责文案代替安全管理。

## 10  抽签 排程与发布

抽签保证不重不漏，排程保证约束可解释。随机性、轮休与第一第二场均衡同时作为可校验规则，而非一个无法解释的随机按钮。

### 抽签

参赛名单与规则确认 → 可选种子队 → 锁定名单 → 随机分组 → 逐队或一键揭晓 → 确认结果。种子分组、人数均衡、轮空和操作日志可核验。重新抽签须记录原因并保留旧结果；开赛后禁止直接重抽覆盖。

| 排程约束 | 处理方式 |
| --- | --- |
| 同队 同场地 同工作人员重叠 | 硬约束；有冲突不允许发布 |
| 休息间隔 | 可配置至少间隔一自然日；由规则明确计算边界 |
| 每日场次与时间窗 | 按场馆开放时段 占场时长 缓冲生成可用时隙 |
| 小组与第一第二场均衡 | 在硬约束满足后优化；无法同时满足时显示取舍 |
| 淘汰赛依赖 | 前序结果未确认时保留晋级占位 不猜测晋级队 |
| 拖动后调整 | 即时校验 显示受影响对象 新旧版本 重新通知 |

### 隔日与开球时间示例

若球队20日出场且规则要求间隔一自然日，则最早22日再次出场；优先选择最小合法间隔，避免无故空闲多日。场地或对手约束不能满足时，给出未满足原因与可调整条件，不能谎报排程成功。

19:30与20:15可作为运营预设，但必须结合真实比赛预计占场时长。例如第一场预计90分钟，第二场同场地20:15会冲突；需调整时刻、时长规则或使用其他球场，不能把预设时间强行视为合法。

### 发布与通知

先发布草案预览与冲突报告，负责人确认后生成正式赛程版本。改期只通知受影响球队和工作人员；用户提醒按同一版本更新。赛程发布时间与公开范围纳入审计。

## 11  现场记录与正式赛果

记分台是可信比赛数据的来源。计时、事件、纠错、确认与榜单组成一个可核验闭环，观众页面只读取结果。

| 阶段 | 主要操作与约束 |
| --- | --- |
| 赛前准备 | 核对冻结名单 首发 裁判与记录人员 规则版本 网络和控制权 |
| 实时比赛 | 服务端权威计时 得分 罚球 犯规 暂停 换人 球员事件 |

| 纠错 | 选中原事件 填原因 查看前后差异 受控更正 不删除历史 |
| 终场提交 | 核对各节总分 球员统计 所有未同步事件后提交待确认 |

| 申诉与更正 | 授权更正版本 重算排名 影响晋级时阻止危险自动更新 |

### 可靠性规则

- 同一比赛仅一个有效写终端；控制权用服务端租约和版本令牌约束。旧终端重连后不能继续覆盖新终端。

- 每个命令有稳定唯一ID。响应丢失时以原ID重试；同一事件只记一次。命令、计分、统计投影与审计必须保持事务一致。

- 断线状态保留待处理命令及原始顺序；重连先核验权威快照、控制权和命令受理结果，再决定重试或人工核对。不能用本地总分覆盖服务器。

- 没有采集的数据为未知，不能替代成0。统计中、待确认、正式与已更正分别标识。球员榜配置最少场次等门槛，避免样本误导。

### 直播协同

权威比分只读供给小程序直播的云端合成，OBS作为后续输入仍可使用独立叠层；数据来源与正式记分一致，视频延迟及媒体PTS分段校准，陈旧和撤权按专项处理。直播人员能在所授权场次执行直播操作，不获得记分、赛果确认或默认对外发布权；旧OverlayGrant与新直播批准独立，不追溯改变其撤销规则。

新直播工作台覆盖设置、采集预览、预检、直播中、异常恢复、结束与观众入口；手机源、各外站转推、平台开播、录像和公开播放分别显示事实与观测时间。外部目标密钥只给有权服务端，手机仅持本场短期入流凭据；同账号直播槽位避免跨场顶流，停播／暂停／撤权后旧代次不得重启。预算、并发、停流止损和计量须在真实开播前验收，直播中断不影响记分。

## 12  同城服务与实际供给

同城页必须让用户分清“可以浏览”与“可以预约”。每个服务由真实服务方、明确时间地点和履约承诺支撑。

| 服务类型 | 详情与筛选 | 下单前条件 |
| --- | --- | --- |
| 球场 | 位置 开放时段 设施 收费或免费 雨天规则 | 商户核验 可预约库存 时隙锁定 取消规则 |
| 裁判 记分 记录 | 服务项目 经验 适用赛事 评价 档期 | 人员核验 职责区分 时间不冲突 服务城市 |
| 直播 摄影 | 设备范围 时长 交付内容 作品授权 | 网络与场馆条件 交付期限 取消责任 |
| 医务保障 | 服务机构 人员证明 服务内容和边界 | 人工核验相应资质；不以自填标签代替审核 |
| 球员邀约 | 位置 时间 条件 参赛资格 意向 | 成人先行；资格 档期 条款均确认后履约 |
| 约赛组局 | 球队 城市 场馆 时间 人数 规则 | 队长确认 场地可用；不自动形成官方赛事 |

### 供给与入驻

服务方提交主体和必要资质 → 平台审核 → 配置服务城市、区县或半径 → 明确项目与档期 → 上架。服务公开页展示经营或履约主体、服务说明、取消与争议处理方式。平台审核标识对应核验项目，不显示无法证明的统一“官方认证”。

### 场地预约与人员服务的区别

球场按可用时隙和库存处理，免费开放球场只展示开放信息，未获经营方授权不能出售预约。地图上搜到球场不等于平台拥有库存或收款授权。人员服务需要确认档期与接受订单，不能用球场库存逻辑代替人员接单。

服务匹配以**实际服务地点＋项目＋日期时段＋已审核覆盖范围**为准。例如人在广州，也能为高州比赛预约覆盖高州的裁判；GPS不限制合法跨城预约。卡片分开展示地点信息、供给能力与本人的真实订单状态；可提交需求或可尝试预约不等于已经订到，不能把“附近”当作“能买”。下单、接单和地点／时间变更按阶段由服务端重新核验，旧订单保留地点、覆盖版本和条款快照；细则见 [定位与服务专项要求](design/LOCATION_SERVICE_REQUIREMENTS.md)。

服务撮合首发采用人工指派与供需登记，先验证供给质量；自动报价、跨城自动派单、培训招生和复杂供给市场后置。无真实服务方时只收集需求，不放置假价格与假库存。

## 13  订单与履约设计

报名、球场、人员、球员邀约和平台套餐使用同一订单骨架，分别保留自己的业务状态与退款规则，不能用“已支付”代替“已完成”。

| 订单类型 | 履约完成依据 | 关键差异 |
| --- | --- | --- |
| 赛事报名 | 审核通过 满足报名规则 | 队伍订单与队员资格分别处理 |
| 保证金 | 赛事结束后按约退还或处理 | 独立资金科目 退还条件和证据 不算收入 |
| 球场预约 | 核销 到场或按规则结束 | 库存锁超时释放 关场改期 天气取消 |
| 人员或球员服务 | 接单 到场 交付 需求方确认 | 接单超时 拒单 替换 迟到 未到场 争议 |
| 平台套餐 | 平台按期限与配额开通权益 | 权益启用 续期 用量 过期 不占用赛事费用 |
| 保险相关 | 以保险机构实际出单状态为准 | 保费与服务订单隔离 不自行形成承保完成 |

### 服务履约状态

需求已提交 → 待服务方确认 → 已确认待履约 → 履约中 → 待客户确认 → 已完成。拒单、超时、取消和争议分别处理；支付状态在独立支付记录中展示。

需要先确认供给的订单在接单后付款。球场即时库存可采用短时锁位后支付。每种订单明确支付截止与失败补偿，避免“付款成功但库存已释放”直接超卖；该场景进入人工或自动退款处理。

### 双方责任与证据

- 确认前展示实际收款商户、履约与退款责任主体、项目、时间地点、费用及规则版本；下单时固化快照，后续机构配置不得追溯改写历史订单。

- 改期、人员替换和跨城服务需双方重新确认；重要变更不能直接沿用旧同意。

- 到场凭证与交付记录在订单内提交；拒绝确认、部分完成或投诉允许提交证据与申诉。自动完成须有明确规则与争议期，不能无条件倒计时结算。

## 14  支付 退款与财务

先确定谁收款、谁履约、谁退款、谁开具相应凭证，再开启收费。采用支付渠道支持的合规收款结算方式，不预设平台资金池或余额钱包。

| 资金类型 | 归属与核对 | 展示要求 |
| --- | --- | --- |
| 平台套餐费 | 平台提供工具的收入 | 独立订单 权益 周期 与平台账单 |
| 赛事报名费 | 具体赛事服务主体收款 | 赛事 主体 费用及规则版本可见 |
| 赛事保证金 | 按约返还的款项 不直接确认为收入 | 报名费与保证金分项 退还 扣减证据 审批 |
| 本地服务费 | 明确实际服务方及平台服务费 | 服务费 抽佣 退款与结算分别记录 |
| 保险保费 | 保险机构对应渠道收取 | 由合作机构提供真实保费与承保凭证 |

### 支付与退款状态

支付：待支付、处理中、成功、失败、已关闭。退款：待审批、提交中、处理中、成功、失败或异常。结算另行记录待结算、可结算、已结算与暂停，三种状态不互相替代。

支付成功以服务端核验为准。通知校验签名、商户、币种、金额与订单，重复或乱序通知只生效一次；无通知时按渠道能力主动查询。相同退款申请不重复执行，累计退款不能超过可退金额。渠道退款通知可能重发，需去重与补查。[4]

### 对账与异常

每日按渠道交易、业务订单、退款与结算记录交叉核对，标记漏单、重单、金额差异和处理中。保留原始通知与处理记录，差异未解决不伪装为对平。保证金的部分扣减走约定规则、证据与审批，余款单独退还。

首发收费上线门槛：主体与合同范围确认，支付商户配置完成，真实小额支付、重复通知、超时查单、部分及全额退款、退款异常和账单核对均通过；未通过时仅开放免费或经人工核验的线下流程。

全国推广依赖可复制的机构入驻与内容服务流程，而不是为每个城市建立一套独立系统。

| 服务与订单 | 项目 档期 履约 退款 对账 | 渠道异常 争议升级 结算审核 |

### 内容与评价

赛事、球队、服务和视频需有发布主体与处理渠道。报名资料不进入内容搜索。提供举报、下架、申诉与更正流程；赛事纠纷与一般内容举报分开处理。评价以真实参与或订单为依据，不开放无证据刷分。

### 城市运营

城市负责人可以维护所授权城市的供给与活动，但不因城市身份自动看到该城市所有机构的私有资料。平台采用“城市范围＋机构范围＋具体操作”授权。跨机构支持访问要有原因、时间范围与记录。

### 广告和公益

地方赞助广告按城市、赛事和时间范围投放，明确标识与数据口径，首发使用固定可控位置。公益或球队经费仅作经授权的透明记账与公示，不设计成公众募款入口或平台余额账户。

## 16  商业模式与推广路径

首选面向真实办赛机构提供赛事工具与服务套餐。观众端保持低门槛，通过赛事分享带来球队、球员和同城需求，再逐步增加交易收入。

| 阶段 | 收入方式 | 开放前提 |
| --- | --- | --- |
| 首个商业产品 | 单赛事工具套餐 或机构周期套餐 | 真实赛事使用 对账可核验 支持成本可控 |
| 运营服务 | 直播 记录 海报或数据服务包 | 真实人员与交付标准 有授权媒体来源 |
| 同城交易 | 服务方订单平台服务费 | 支付退款 供给核验 履约和纠纷流程通过 |
| 广告赞助 | 城市或赛事的赞助展示 | 真实曝光清楚标识 订单与投放统计可核对 |
| 后续权益 | 机构配额 媒体容量 额外席位 | 成本与使用量可度量 不虚构无限资源 |

### 价格与成本

本方案先确定收费对象与计费单位，不把试算价格写成正式售价。赛事数量、工作人员席位、媒体容量和额外服务分别定价；存储、转码、直播流量、短信与客服纳入成本。全国视频流量不能承诺由一个固定低价服务器预算包办。

### 逐城复制

阶段一：全国受理并审核机构申请，高州先运行真实办赛样板；其他机构通过审核后可发布其有能力组织的真实赛事。阶段二：邀请相邻城市复制入驻、培训、赛事模板与支持流程。阶段三：扩大服务运营城市，已核验供给逐城开放交易。

主要增长入口是领队邀请队员、赛事观赛码、比分与赛程分享、球队公共主页和赛后数据内容。每个入口都回到可持续使用的赛事与档案，不依靠补贴或虚假全国数据制造活跃。

### 城市开放门槛

以真实机构、可履约服务、负责人、退款与投诉处理能力作为门槛；供给不足城市只开放内容与需求登记。合作机构数量和活跃球队数以试运营结果定阈值，不用全国注册量替代当地履约能力。

### 推荐部署结构

小程序与网页共享API；数据库维护权威数据与事务；worker处理通知、媒体、导出与对账；对象存储与CDN承接文件和公开内容。直播能力、配额及费用按实际供应商接入核验。

业务变更与待处理事件在同一事务落库，worker可重试执行，不依赖浏览器保持打开。公开数据可按版本缓存，缓存键包含授权范围；私有响应不进入公开缓存。

### 接口一致性

金额用整数最小货币单位并记币种，时间按赛事时区显示；资料删除与必要审计保留分别处理。写入携带操作ID及预期版本，冲突返回错误码和最新版本。切城或切换身份后废弃旧请求与私有缓存。接口路径与框架以仓库核验为准。

### 页面与交互约束

### 核心指标

北极星指标选择每周完成且正式公示的真实比赛数，辅以组织者复用率和每场可核验数据完整率。服务业务看真实履约完成率、取消率、争议率和退款处理时长；城市看活跃机构、活跃球队与可服务供给，而不只看注册量。

### 运行与事故处理

监测API、数据库、任务队列、媒体与支付回调；报警明确责任人和处理手册。对账异常、待同步命令和失败通知有重试与人工入口。按赛事负载验证发布与回滚，运行日志排除密钥、完整证件和支付敏感信息。

保留当前实际配置和恢复证据；多环境验证与隔离测试不需要另建对外测试域名，正式业务域名继续沿用项目既定设置。
